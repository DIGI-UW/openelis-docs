How-to · Lab administrators and lab IT

OpenELIS 3.3.0. This page describes analyser setup as it works in 3.3.0 (not yet released at the time of writing): OpenELIS pairs with the Analyzer Bridge by certificate, setup is for Global Admins only, the wizard has four steps, and each analyser keeps its own mapping. Sites on 3.2.x use Set up an analyzer (before 3.3.0).

At a glance

Purpose

Connect a laboratory analyser so its results arrive in OpenELIS against the right tests.

You'll end up with

An active analyser with its own mapping of analyser codes to OpenELIS tests, and a Bridge connection that receives its results.

Who does this

A Global Admin, usually with lab IT for the connection details. In 3.3.0 analyser setup, types, mappings and pairing are restricted to Global Admin.

Before you start

OpenELIS must be paired with the Analyzer Bridge (see Install the Analyzer Bridge). Know the instrument model, the lab units it serves, which assays it runs, and how it connects (network or serial, and the name it sends in its messages).

Where

Main menu → Analysers → Analyzers List → Add Analyser

The Analysers list

Main menu → Analysers → Analyzers List. The top of the page shows whether OpenELIS is paired with the Bridge and, when the Bridge is holding results it could not deliver, a banner with Review undelivered results. Tiles count Total analysers, Active, In setup and Needs attention. The table shows Name, Connection, Lab Units, Analyser type, Status and Actions.

{{IMG:01-analysers-list.png}}

Figure 1. The Analysers list with one active GeneXpert and four inactive analysers.

Analyser types

An analyser type is the reusable setup behind an analyser: the protocol, the codes it sends, and the rules that recognise control material. Identical analysers share one type. Main menu → Analysers → Analyser Types lists each type with its manufacturer, model and revision, a Shipped or Site-created badge, the Protocol (ASTM, HL7 or FILE), Tests mapped, Results mapped, Used by and Status. Filter by Created, Protocol and Mapping status, or show deactivated types.

{{IMG:02-analyser-types.png}}

Figure 2. Analyser Types. The six types come from the Bridge's profiles; Cepheid GeneXpert (ASTM Mode) is used by one analyser.

In 3.3.0 a type's mappings are defaults for new analysers, not a shared mapping. The row's View default mappings shows what a new analyser of that type would start with, matched by standard codes against your catalog; nothing there is saved. Each analyser keeps its own mapping, set in the wizard's Verify step. The row menu also offers Duplicate Profile, View history and Deactivate. Deactivate a type rather than deleting it, so its history is kept.

Step 1: Instrument

  1. Select Add Analyser. The setup panel opens with four steps: Instrument, Assays, Verify and Connect.

  2. Under Analyser type, search for and choose the type for your instrument. Each option reads name, manufacturer, protocol and revision. Choose the listed type even if the instrument will only send results: whether it also receives orders is set later, in Connect.

  3. Enter an Analyser name that tells this instrument apart from others of the same type, for example its serial number and location, and choose its Lab units.

  4. Select Continue to Assays. The analyser is created at this point, so it stays in the list even if you close the panel.

    {{IMG:03-step1-instrument.png}}

    Figure 3. Step 1 for a GeneXpert in the TB laboratory.

Instrument not listed? under the type field is for an instrument with no matching type; it is not covered on this page.

Step 2: Assays

  1. Turn on the assays this instrument runs, as set in its own host test codes. Each assay shows whether your catalog has a matching test (Matches Xpert MTB/RIF, Several tests in this lab's catalog match, or No test in this lab's catalog). Assays with a match start switched on. Verify maps only the assays that are on; a result for an assay that is off is held, never lost.

    {{IMG:04-step2-assays.png}}

    Figure 4. A TB laboratory's GeneXpert with only MTB complex switched on.

  2. Select Continue to Verify.

Step 3: Verify

Verify is where you set this analyser's own mapping. The summary shows Tests mapped, Results mapped and Confirmation (Not confirmed, Current or Stale). Below it, every record and result value of the assays that are on is listed under Test and result mappings.

  1. For each analyser code that says Needs mapping, expand it and either choose the OpenELIS test it should file against (search by name, code or LOINC) or tick Do not receive. A code that matches several catalog tests says Not mapped: several tests in this lab's catalog carry its code. Choose one.

  2. When a test has more than one result component, choose the component this record lands on (Call result for or OpenELIS component for the code).

  3. Map the coded result values listed under Results for that test. If the OpenELIS test has no coded result options, the page says This Test has no active result options and links to Add result options in Test Catalog.

    {{IMG:05-step3-verify-records.png}}

    Figure 5. Verify with the HIV viral load sub-records set to Do not receive and MTB complex mapped. With records still unresolved, Continue to Connect stays disabled.

  4. Select Save mapping. Review changes before saving lists each change; select Save changes. The page confirms Mappings saved.

    {{IMG:06-review-changes.png}}

    Figure 6. Review changes before saving.

  5. Check Control result recognition: the rules that identify quality-control material so it is not filed as a patient result (for the GeneXpert type, Order field 12 equals Q). Then select Confirm mappings and control recognition. Confirmation turns Current, with who confirmed it and when. Changing the mapping or the assays afterwards makes it Stale until you confirm again.

  6. Select Continue to Connect. It is enabled only when every record and value of the assays that are on is mapped or set to Do not receive, and the mapping is confirmed. If a record cannot be mapped yet, turn its assay off in Assays.

    {{IMG:07-step3-confirmed.png}}

    Figure 7. The confirmed mapping, with Continue to Connect enabled.

Step 4: Connect

  1. Set Data flow (Results only or Two-way), Transport (Network (TCP/IP) or Serial (RS-232)) and Connection role (Server or Client).

  2. Host is the analyser's IP address. It is optional when the analyser connects to the Bridge; leave it blank if the analyser reaches the Bridge through NAT or a proxy. Instrument system name is the name the instrument sends in its messages (ASTM H.5 or HL7 MSH-3), such as the GeneXpert System Name; it is needed when several analysers share a port and address. Set the Decimal separator in results.

    {{IMG:08-step4-connect.png}}

    Figure 8. Connect for a network analyser that connects to the Bridge.

  3. Select Test connection. Connection evidence reports the Bridge listener (for an ASTM analyser, the shared listener on port 12001) and, if a host is saved, whether the analyser answered. Activation readiness says whether the analyser can be activated.

    {{IMG:09-test-connection.png}}

    Figure 9. Connection ready, with the Bridge listener on port 12001 and the analyser ready to activate.

  4. Select Finish and activate, or Save and finish later to leave it in setup. The analyser is listed as Active with Bridge connection configured.

Statuses

Status

Meaning

Setup

Created but not yet activated.

Active

Running and receiving through its Bridge connection.

Needs attention

Running, but something needs review, commonly held results.

Inactive

Deactivated. Configuration and history are kept, and it can be reactivated.

Managing an existing analyser

The row's Actions menu on an active analyser offers View results, Edit setup, Configure connection, Quality Control and Deactivate; an inactive analyser offers Reactivate instead of Deactivate and Configure connection. Edit setup and Configure connection reopen the wizard at the matching step.

Results the Bridge received but could not deliver (for example from a sender that matches no saved connection) are listed under Review undelivered results; see Map analyzer codes, resolve held results, and run QC.

Tips

  • If the analyser type list is empty or setup cannot load types, check the pairing banner at the top of the Analysers page first.

  • Turn off the assays an instrument does not run. That keeps Verify short and lets you continue to Connect.

  • Mappings now belong to each analyser. Changing one GeneXpert's mapping does not change another's, and a type's default mappings only affect analysers set up later.

  • The analyser is saved at step 1. Use the row's Deactivate action if you started one by mistake.

Known issues

  • While records are unresolved, Verify says You can confirm and connect; affected results will be saved for correction before use, but Continue to Connect stays disabled until every record of the assays that are on is mapped or excluded.

  • In the OpenELIS test search, several tests appear twice with the same name and code (for example HIV Viral Load 20447-9), with nothing to tell them apart.

  • Coded result values show every language the profile carries (for example DETECTED, DÉTECTÉ, ERMITTELT and their Russian and Ukrainian forms) as separate values to map.

Not yet documented

Adopting a newer revision of a type for an existing analyser (/analyzers/{id}/adoption, shown only when a newer revision exists); Instrument not listed? and Create Profile; Two-way data flow and orders; serial (RS-232) connections; View results; FILE and HL7 analysers.
