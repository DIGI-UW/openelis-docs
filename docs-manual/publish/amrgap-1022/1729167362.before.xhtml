Overview

A microbiology case is opened by the order itself: when a test marked as opening a case is ordered, OpenELIS creates the case on the bench. Everything the bench then needs to interpret growth and susceptibility comes from Microbiology reference data, which has six tabs: Molecular resistance mappings, Organisms, Antibiotics, AST panels, Breakpoint standards and Patient origins.

Step 1: Mark the tests that open a case

Open the test in the Test Catalogue Editor (Main menu → Admin → Test Catalogue Management, then the test) and go to Basic Info. For a culture test set:

  • AMR surveillance test: Yes, if its results feed AMR surveillance.
  • Opens a Microbiology case: Yes.
  • Case role: for example Culture.
  • Collected in sets: Yes for tests collected as sets, such as blood cultures.

Figure 1. Basic Info for Blood culture (Whole Blood): AMR surveillance test, Opens a Microbiology case and Collected in sets all Yes, with Case role Culture.

Step 2: Keep the organism list

Go to Main menu → Admin → Microbiology reference data → Organisms, described as the organism vocabulary used by culture identification and AST. Each organism has a WHONET code, an Organism group, an Initial significance (for example USUALLY, POSSIBLE or RARE) and a Default AST panel. Use Add organism to add one, and the row menu to change it.

Figure 2. The Organisms tab: Escherichia coli (eco) in Enterobacterales with the Enterobacterales urine panel as its default, and other organisms with their groups and significance.

Step 3: Keep the antibiotic list

On the Antibiotics tab, each antibiotic has a WHONET code, a Class, a Route (for example IV, ORAL or BOTH) and a status. Add antibiotic opens a dialog with Name, WHONET code, Class, TB resistance role, Route and Notes.

Figure 3. Adding Amikacin: WHONET code AMK, class Aminoglycosides, Not a TB classification drug, route IV.

Step 4: Maintain AST panels

On the AST panels tab, each panel lists the antibiotics tested for a group of organisms. Changing a panel is done with Publish new version from its row menu. The dialog notes that saving creates a new panel version and that existing AST runs keep their original version. It holds the Susceptibility protocol, the Name, Available for new work, and the list of antibiotics, each with a Tier and a Report behavior and arrows to reorder them. Pick an antibiotic and press Add to add it to the panel.

Figure 4. Publish new version for the Enterobacterales urine panel: General susceptibility, Ampicillin, Ceftriaxone, Ciprofloxacin and Gentamicin at tier 1, reported Always.

Step 5: Check the breakpoint standard in use

The Breakpoint standards tab lists the loaded standards with Publisher, Version, Status, Effective date and the number of Rules. The Active standard is the one used for new AST runs; others show Loaded. Import CSV loads a standard from a file.

Figure 5. Breakpoint standards: CLSI 2026 Active with 7 rules, and a second CLSI set Loaded but not active.

Open a standard to see its rules. Each rule gives the Organism or group, Antibiotic, Method and the Susceptible, Intermediate and Resistant values, with its Source (for example Imported). Filter by organism, antibiotic, method or specimen context. Add local correction adds a laboratory-specific rule.

Figure 6. The rules of CLSI 2026: MIC breakpoints for Enterobacterales against Ciprofloxacin, Gentamicin, Meropenem and Ampicillin, all Imported.

Step 6: Give each specimen type its WHONET code

In the Sample Type Editor (Main menu → Admin → Test Catalogue Management → Sample Type Editor, then the sample type), WHONET specimen code is the code written to the WHONET SPECIMEN_TYPE field, up to 5 characters. Use for microbiology isolates marks sample types used for isolates.

Figure 7. The Urines sample type with WHONET specimen code ur.

Tips

  • Set the WHONET code on every organism, antibiotic and specimen type you report. Rows without a mapping cannot go into the WHONET export.
  • Panels are versioned, so changing a panel does not rewrite results already recorded.
  • In the rules list, a single intermediate value is shown as a range with the same number at both ends (for example 4–4).
  • Known issue OGC-1527: when the server rejects a reference-data entry, the message can show an internal message key instead of the field name.
  • Reference data on the test server includes panels and a standard created for automated testing (names starting with QA). They are not part of a standard installation.

Not yet available

  • Breakpoints for disk diffusion (zone diameters). Only MIC rules were present on the test server.
  • AST reporting rules, one-click suggestions, AMR for R reference data, infection control alerts and AST QC are planned for Microbiology V3 (OGC-1528).
