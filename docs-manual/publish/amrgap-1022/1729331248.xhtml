Overview

The WHONET export, headed Routine bacteriology surveillance, reviews finalised culture and AST data before generating the OpenELIS surveillance CSV for WHONET validation. It has three steps: Configure, Preview and Generate.

Step 1: Configure the export

Go to Main menu → Reports → WHONET export. Under Configure export, choose the reporting period and the isolates to include:

  • Reporting period (for example This Month), which fills From and To.
  • Specimen types, Organisms and Patient origins to narrow the export, and Inclusion values.
  • Apply first-isolate selection: collapses repeat isolates for the same patient and organism within the window. Adjust first-isolate policy changes how this is done.
  • Culture purpose: clinical cultures are included by default. Tick Include active screening or carriage cultures or Include environmental isolates only when the surveillance question needs them.
  • Include survey or study Programs: add programs whose cultures should be included.

Figure 1. Configure export for October 2026, with first-isolate selection applied and only clinical cultures included.

Step 2: Check the preview

Move on to Preview. The counts show how the population narrows at each stage: finalised cases, isolates found, after the specimen, organism and origin filters, clinical, screening and unspecified cultures, after culture-purpose selection, isolates included, after de-duplication, mappable isolates, eligible rows and rows excluded. Eligible AST rows lists the reviewed, reportable AST readings that have the mappings the export needs, with the lab number, specimen, organism and antibiotic codes, S / I / R and method.

Figure 2. The preview: two finalised cases and two isolates, giving 8 eligible AST rows for Escherichia coli from urine and none excluded.

Step 3: Generate the file

When the preview is right, press Generate CSV. The browser downloads the file, named for the reporting period (for example WHONET_2026-10-01_to_2026-10-31.csv), and a green notice reads "CSV generated: The validated export was downloaded and its audit summary was recorded." The preview stays on screen, so you can compare the file with it.

What the file contains

The file is comma-separated with every value in double quotes. The first line is a header of 20 columns, and each following line is one AST result: one antibiotic tested against one isolate. An isolate tested against five antibiotics gives five lines, each repeating the patient, lab number, specimen and organism. The number of lines matches Eligible rows in the preview (8 in Figure 3). Organisms, antibiotics, specimen types and origins are written as their WHONET codes.

For example, the ampicillin result for the urine case DEV01260000000000005 is written as: patient identifier, name, F, date of birth, 2026-10-21, DEV01260000000000005, 2026-10-21, ur, AMP, eco, R, MIC, two empty GPS values, OUT, DIAGNOSTIC, LOCAL, and two empty site values.

Tips

  • If rows are excluded, check that the organism, antibiotic and specimen type carry a WHONET code.
  • The preview uses the codes, not names (for example eco for Escherichia coli and ur for urine), so it shows what WHONET will receive.
  • The file holds names, dates of birth and national identifiers. Store and share it as patient-identifiable data.
  • Each Generate CSV records an audit summary, so generate the file once the preview is final.
  • On the test server, BIRTH_DATE in the file was one day later than the date of birth shown on the case (1988-04-12 against 4/11/1988).
  • The worklist's Surveillance scope filters change the AST rows on the worklist only; as its note says, they do not change the export population.
