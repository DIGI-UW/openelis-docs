Review QC and act on violations

At a glance

PurposeCheck each day that control results have arrived from your analyzers and that no Westgard rule has been breached, and deal with any violation before patient results are released.
You'll end up withEvery instrument showing In Control on the QC Dashboard, and any violation from the run acknowledged, with the corrective action recorded in your laboratory's non-conformance process.
Who does thisThe bench analyst running the controls, and the supervisor who signs off the run. Access is set by user permissions and can be configured by your administrator.
Before you startControls have been run on the analyzer per your SOP and the analyzer has sent its results to OpenELIS. QC for the analyzer and test has been set up (see Set up QC for an instrument).
WhereMain menu → Analyzers → Quality Control → QC Dashboard

Control results are not entered on these screens. They arrive from the analyzer, are matched to the active control lot for that analyzer and test, and are evaluated against the pair's Westgard rules. The QC Dashboard is where you read the outcome. It has two tabs: Instruments, which summarises each analyzer's current status, and Alerts, which lists violations to be acknowledged.

Step-by-step

Step 1. Open the QC Dashboard. Four tiles across the top summarise the position: Instruments In Control, Warning Status, Out of Control (each with a percentage of total instruments) and Overall QC Pass Rate. Last Updated and a Refresh action sit at the top right.

{{IMG:01-qc-dashboard-instruments.png}}

Figure 1. The QC Dashboard with the Instruments tab selected, before any control results have arrived.

Step 2. On the Instruments tab, read the Instrument Quality Control Status table. Its columns are Instrument Name, Type, Location, Status, Analytes, Recent Violations, Last Update and Actions, with Search instruments... above. An analyzer that has a lot and rules but no control results yet is not listed — the table reads No instruments found, as in Figure 1 — so an unexpectedly missing analyzer means results are not reaching OpenELIS (see Why is my QC chart empty?).

Step 3. Open the Alerts tab. QC Violations & Alerts is split into Active QC Violations (unacknowledged, requiring attention) and Acknowledged Violations. A Time Period filter limits the view to Last 24 Hours, Last 72 Hours (the default), Last 7 Days, Last 30 Days or All Time.

{{IMG:02-qc-dashboard-alerts.png}}

Figure 2. The Alerts tab with no active or acknowledged violations in the last 72 hours.

{{IMG:03-alerts-time-period.png}}

Figure 3. The Time Period filter on the Alerts tab.

Step 4. For each active violation, investigate the run on the analyzer (reagent, calibration, control material, maintenance), take the corrective action your SOP requires, and then acknowledge the violation so it moves to Acknowledged Violations.

This step has not yet been verified on a live instance: the test instance had no control results, so no violation could be raised or acknowledged. Confirm the acknowledge action and what it records before publishing.

Step 5. Where a violation was a rejection, record the event and its corrective action as a non-conforming event under Non-Conform, following your laboratory's procedure, before releasing the affected patient results.

This step has not yet been verified on a live instance. Whether a rejection creates a non-conforming event automatically, or must be reported by hand, has not been confirmed. Confirm before publishing.

Tips

  • An empty Instruments table is a diagnosis, not proof that QC is working or broken: it means no control result has been matched to an active lot. Work through Why is my QC chart empty? before assuming the instrument is fine.
  • With no instruments, the Overall QC Pass Rate tile shows 0% with a green tick. Read it together with the instrument counts.
  • The Time Period filter sits on the Alerts tab; there is no equivalent filter on the Instruments tab.
  • Use Refresh (top right) after the analyzer has finished sending a run to reload the dashboard; Last Updated shows the time of the last reload.
