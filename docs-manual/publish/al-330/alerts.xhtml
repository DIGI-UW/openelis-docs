OpenELIS 3.3.0. This page describes the Alerts Dashboard as it works in 3.3.0 (not yet released at the time of writing), where overdue STAT orders raise alerts and alerts carry their real creation date (OGC-1372). It is a draft for review.

How-to · Supervisors, quality officers and bench staff

At a glance

Purpose

See the alerts OpenELIS has raised (overdue STAT orders, EQA deadlines, critical results, rejected referrals and others) and record what was done about each one.

You'll end up with

Each alert acknowledged (someone is on it) or resolved (it is dealt with), with a comment that says what was done.

Who does this

Supervisors and staff who follow up urgent work. Access is set by user permissions and can be configured by your administrator.

Before you start

Nothing. Alerts are raised automatically.

Where

Main menu → Alerts

Step 1: Read the dashboard

  1. Open Main menu → Alerts. Four tiles count open alerts: Critical Alerts, EQA Deadlines, Overdue STAT Orders and Samples Expiring. An alert stops counting once it is acknowledged.

  2. The table lists each alert's Type, Severity (Warning or Critical), Message, Status (Open, Acknowledged or Resolved), Created date and time, and the next action. Narrow it with Alert Type, Severity and Status, or Search alerts.

    {{IMG:01-alerts-dashboard.png}}

    Figure 1. The Alerts Dashboard with a resolved referral alert, an acknowledged and an open overdue STAT order.

  3. Below the table, EQA Deadline Summary groups upcoming EQA submission deadlines by provider, with View All.

Step 2: Acknowledge an alert

  1. Select Acknowledge on the alert's row. The Acknowledge Alert dialog repeats the message.

  2. For a critical alert, enter an Acknowledgment Comment: the dialog says A comment is required to acknowledge a critical alert, and Acknowledge stays disabled until you type one. Say what you are doing about it.

    {{IMG:02-acknowledge.png}}

    Figure 2. Acknowledging an overdue STAT order with a comment.

  3. Select Acknowledge. The alert's status becomes Acknowledged, its action becomes Resolve, and the tiles drop by one.

Step 3: Resolve an alert

  1. When the problem is dealt with, select Resolve. The Resolve Alert dialog requires a Resolution Comment.

  2. Select Resolve. The status becomes Resolved and the row has no further action.

Overdue STAT orders

Every five minutes OpenELIS checks STAT samples received in the last seven days. When a STAT sample still has a test with no result (not started, or rejected and awaiting a new result) longer than the STAT turnaround, it raises a critical STAT Overdue alert: STAT order lab number has no result 60 minutes after receipt. The turnaround is the statTurnaroundMinutes setting in Order Entry Configuration (default 60 minutes; see General Configurations reference). Each sample raises one STAT Overdue alert at most, so a resolved alert does not come back.

Alert types

The Alert Type filter lists: Freezer Temperature, Freezer Humidity, Freezer Offline, Equipment Failure, Inventory Low, Sample Tracking, Other, EQA Deadline, Sample Expiration, STAT Upcoming, STAT Overdue, Unacknowledged Critical, Required By Deadline, Referral Critical Result, Referral Rejected, Critical Result, EQA Submission Failed and Microbiology Critical. This page was written from STAT Overdue, EQA Deadline and Referral Rejected alerts; the others were not observed.

Tips

  • Acknowledge early, resolve when done. Acknowledging tells others someone is on it, and takes the alert out of the tile counts.

  • Write comments for the next person: what you did, who you called, and when the result is due.

  • Use the Status filter to show only Open alerts at the start of a shift.

Not covered on this page

The notification bell in the header, alert types other than STAT Overdue, EQA Deadline and Referral Rejected, View All in EQA Deadline Summary, and who receives alerts outside the dashboard.
