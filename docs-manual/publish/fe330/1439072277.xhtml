This page describes OpenELIS 3.3.0. Updated on 12 October 2026: results are flagged Normal or Abnormal as you type, each Save asks for your electronic signature where signatures are switched on, and the unified worklist is now the only Results Entry screen. For OpenELIS 3.2.2 and 3.2.3, see Enter and save results (before 3.3.0).

At a glance

Purpose

Enter test results for samples that are awaiting results, and save each one so it moves on to validation.

You'll end up with

Each saved result shown read-only with the status Accepted by technician and a Normal or Abnormal flag, ready for the validator.

Who does this

Analysts. Access is set by user permissions and can be configured by your administrator.

Before you start

Orders whose samples have been received and whose tests are still awaiting results; the measured values to enter; and the lab number, the lab unit or the patient. Where electronic signatures are on, your OpenELIS password.

Where

Main menu → Results → Results Entry

One screen for all result entry

Results Entry is a single worklist. Every pending test is a row carrying the sample and patient, the test, the sample type, the reference range, a result control that matches the test's result type, a status and a flag. You load the rows you want by lab number, by lab unit or by patient, enter values, and save one row at a time.

In OpenELIS 3.3.0 this is the only Results Entry screen. The older By Unit, By Patient and By Order screens, and the resultsEntryUnifiedRoute setting that switched between them, are gone: their old addresses open this worklist, and Result Entry Configuration no longer lists the setting. Sites on earlier releases can still see the older screens; see Results Entry (legacy screen).

Figure 1. The Results worklist as it opens: Search by lab number, Lab Unit, Test date, Search by patient and Load results across the top, a single All (0) chip, and an empty table.

Steps

  1. Find the tests to result. There are three ways, and each fills the table with one row per test:

    • By lab number. Type or scan the lab number into Search (its placeholder reads Search by lab number) and press Enter. Every test on that order loads, whatever lab unit it belongs to.

    • By lab unit. Pick a unit from Lab Unit (for example Hematology) and click Load results. The tests for that unit load, with a chip for each status present. The Test date field sits beside it; it was not exercised for this page.

    • By patient. Search by patient opens a patient search with Patient Id, Previous Lab Number, Last Name, First Name, Date of Birth and Sex, and Search, External Search and Clear. Pick the patient in the results: their tests load straight away, a Selected patient tag names them, and Select another patient and Clear appear beside it. Search and Lab Unit are greyed out while a patient is selected.

    Figure 2. Searching by lab number: the five Hematology tests on one order load, each with its reference range, an empty Result box and the status Not started.

    Figure 3. Searching by patient: Agnes Bunari selected, with Select another patient and Clear, and her five tests loaded.

  2. Read the row. Sample / Patient shows the lab number with the patient's name, identifier, sex and date of birth beneath it. Test names the test and its sample type. Method and Analyser show a dash until something is recorded there. Reference Range shows the normal range and unit. Status starts at Not started. The Flag and Actions columns sit to the right; on a narrow window, scroll the table sideways to see them.

  3. Enter the result. The control in the Result column matches the test: a numeric test gets a number box, and a test with a fixed list of answers gets a drop-down. As soon as you enter a value:

    • the Flag column shows Normal (green) for a value inside the reference range or Abnormal (amber, with a warning sign) for one outside it, and a coloured bar appears beside the Result box;

    • a Save button appears in that row's Actions column.

    Figure 4. Values typed into all five rows. Platelets at 512 against 150.0 to 400.0 is flagged Abnormal; the other four are Normal. Each row now has its own Save.

  4. Add detail if you need to. Click the arrow at the left of a row to expand it. The panel repeats the patient, the test and the Sample Kind (for example Client sample), then shows:

    • the Result with its unit, flag and reference range;

    • Method and Analyser lists (Analyser defaults to Not from an instrument; the help text says Method is the analyser type; Analyser is the specific instrument);

    • Notes, with a Context: Entry tag (Set automatically from what you are doing), a Visibility choice of In lab only or Send with result, and an Add a note box;

    • a second Save, Report Non-Conformity and Refer this test;

    • Reagents, QC & Controls, tagged capture mode: manual (optional), with Reagent lots used and Dilution (Measured value, Dilution factor). If no reagents are linked to the test, the section says links are configured in the Test Catalog;

    • Reference & Context, a set of collapsed sections with a one-line summary each: Order info (requester, priority and site), Aliquots, Interpretation, Program info, Storage & sample disposal, Attachments and History (this analysis). Reset layout sits beside the heading.

    Only the result value was driven for this page; the other controls are described as they appear.

    Figure 5. The Platelets row expanded: the result with its Abnormal flag and range, Method and Analyser, Notes with the Entry context and Visibility, Save, Report Non-Conformity and Refer this test, and Reagents, QC & Controls.

    Figure 6. Lower in the expanded row: Dilution and the Reference & Context sections, each with its summary.

  5. Save the row, and sign if asked. Click Save in the row's Actions column (or in the expanded panel). Where electronic signatures are switched on, an Electronic Signature dialog opens first. It shows Signing as with your user name, the Action (for example Save DEV01260000000000506 - White Blood Cells Count (WBC)(Whole Blood)) and the Signature Meaning (Authored), and states that you are creating a legally binding electronic signature per 21 CFR Part 11.

    • Your first signature in a session asks for Username and Password: This is your first signature in this session.

    • Later signatures in the same session ask only for the password: You have an active signing session. Enter your password to continue.

    Click Sign. Cancel closes the dialog without saving.

    Figure 7. The first signature of a session: Action and Signature Meaning, with Username and Password.

    Figure 8. A later signature in the same session asks only for the password.

    Once saved, the row's status changes to Accepted by technician, the value becomes read-only, and Edit replaces Save. The chip row updates, for example Not started (4) and Accepted by technician (1). Each row saves on its own; there is no single Save for the whole list.

    Figure 9. After the first Save: White Blood Cells Count shows Accepted by technician with Edit, and the chips read Not started (4) and Accepted by technician (1).

  6. Work through what is left. Click a status chip to filter the table to that status: Not started shows only the rows still needing a result, and All shows everything again. Repeat steps 3 to 5 for each remaining row.

    Figure 10. All five results saved and signed: Accepted by technician (5), with the flags kept beside each value.

  7. Correct a saved value, if needed. Edit on a saved row puts the value back into an editable box. Saving the corrected value has not yet been verified on a live instance. Confirm before publishing.

    Figure 11. Edit on the White Blood Cells Count row: the saved value 6.8 is editable again.

Field reference

Column or control

Notes

Search

Search by lab number. Press Enter to load every test on that order.

Lab Unit

The lab section whose tests you want. Use with Load results.

Test date

A date field (dd/mm/yyyy) beside Lab Unit. Not exercised for this page.

Search by patient

Patient search. Selecting a patient loads their tests; Select another patient and Clear follow.

Status chips

All, plus one chip per status present in the loaded rows, each with a count. Click to filter.

Sample / Patient

Lab number, with the patient's name, identifier, sex and date of birth beneath it.

Test

Test name with its sample type in brackets.

Method / Analyser

Shown as a dash until set in the expanded row.

Sample

The sample type, for example Whole Blood.

Reference Range

The normal range and unit for the test.

Result

A number box or a drop-down, depending on the test's result type. Read-only after Save until Edit.

Status

Not started before Save; Accepted by technician after. Rows sent back by validation can read Not accepted by biologist.

Flag

Normal or Abnormal against the reference range, shown as soon as a value is entered and kept after Save.

Actions

Empty until a value is entered; then Save; then Edit once saved.

Electronic Signature

Shown on Save where signatures are on. Username and Password on the first signature of a session, then Password only.

Tips

  • Searching by lab number loads every test on the order regardless of lab unit, which is the quickest way to result a single sample.

  • The Save button only appears after a value is entered. If you do not see it, the Result box is still empty.

  • Read the Flag before you save: an Abnormal flag is your cue to check the value against the sample before it goes to the validator.

  • The Flag and Actions columns can fall off the right edge of the table on smaller windows. The table scrolls sideways.

  • Electronic signatures are switched on per site. If Save completes without a signature dialog, they are off at your site. See Electronic Signatures.

  • A pop-up alert for a result outside the valid range is controlled by alertWhenInvalidResult under Main menu → Admin → General Configurations → Result Entry Configuration. It was off on the reference site, so no such alert appears in these figures.

Not yet documented

The Test date filter; saving a value after Edit; Report Non-Conformity and Refer this test; the Method and Analyser choices; notes; the Reference & Context sections; tests with more than one result component; drop-down and titer result controls; critical results and their acknowledgment. None of these was driven for this page.
