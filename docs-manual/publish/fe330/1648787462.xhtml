How-to · Reception staff

Part of the clinical order pipeline: Enter Order → Prepare Samples → Sample check

panel_c1

This page describes OpenELIS 3.3.0. Updated on 12 October 2026 for the Possible matches check when a new patient is created and the new rule that every sample needs a test before Save and next. Sites on 3.2.x use the four-stage flow (Enter Order → Collect → Label & Store → QA Review); see Enter a clinical order (before 3.3.0).

At a glance

Purpose

Register a clinical order: the patient, the requesting site and provider, and at least one sample type, with its tests if you know them.

You'll end up with

A saved order with a lab number, status Entered, ready for Prepare Samples.

Who does this

Reception staff. Access is set by user permissions and can be configured by your administrator.

Before you start

The request form: the patient's details or identifier, the requesting site and provider, and the specimen type.

Where

Main menu → Order → Add Clinical Order → Enter Order

Order entry now has three steps

A clinical order goes through Enter Order, Prepare Samples and Sample check. The step bar at the top of each screen shows where the order is: the step in hand shows what is left to do (for example 2 to do) or Ready, steps not reached read Not started, and finished steps read Done with the time. The card under the step bar shows the lab number, the order status and a step counter such as 1/3 steps.

Labelling and storage, which used to be a separate Label & Store step, are now part of Prepare Samples. The old QA Review step is now Sample check.

Figure 1. The top of Enter Order: the step bar, the order card with its lab number and In Progress status, and the Lab Number field.

Before the form: what your site shows

Several fields on this screen are switched on or off per site, under Main menu → Admin → General Configurations → Order Entry Configuration. See the General Configurations reference. If a field described here is missing, or you see one that is not described, the cause is usually configuration. This page was captured with EQA, Program and payment tracking on.

Steps

  1. Check the lab number. A lab number is already in the field when the screen opens, with Generate Lab Number beside it. The Scan barcode or enter lab number box at the top is for finding an existing order.

  2. Set sample handling if it applies. Tick External quality assessment (EQA) sample for an EQA specimen. This order has no patient is shown greyed out on this screen.

  3. Find the patient. Under Patient, Search for Patient is open by default. Its fields are Patient Id, Previous Lab Number, Last Name, First Name, Date of Birth and Sex. The help text says any combination works and that names match exactly or by their first letters: on the reference site Kau found both Kaupa records, while the misspelling Kaupx found nobody. Search looks in OpenELIS. External Search queries the Client Registry and needs at least a name and a date of birth. Pick the patient with the radio button in the results.

    The patient then shows as a Selected card with name, date of birth, sex and ID, an Edit details link and a Clear link.

    Figure 2. A patient found by last name and selected. The Selected card replaces the search form.

  4. Or register a new patient. If the search finds nobody, choose New Patient. Sex and Date of Birth are marked required. Patient ID / Clinic ID / UR number, National ID, Last Name, First Name, Primary phone and Email are optional; Age/Years, Months and Days fill in from the date of birth. Phone numbers must match the format shown under the field (on the reference site, xxxx-xxxx). Emergency Contact Info, Additional Information and Identification Documents are collapsible sections.

    Press Create patient. The screen confirms The new patient is created when the order is saved. Nothing is written until you save the order.

    Figure 3. The New Patient form filled in for a new patient.

  5. Check any possible matches. If OpenELIS already holds records that look like the patient you are creating, Create patient opens a Possible matches dialog instead: These records look similar to the one you are creating. Use one of them, or create a new record. Each record shows the name, date of birth and identifier, with the matching parts highlighted and a line such as Matched on: name, date of birth.

    Use this one selects that existing patient, and the patient then shows as a Selected card, just as if you had found them by search. The dialog also offers Create new anyway and Cancel.

    Use an existing record whenever it is the same person. A second record splits the patient's history across two files.

    Figure 4. Possible matches for a new patient named Joseph Kaupa, born 03/02/1975. Two existing records match on name and date of birth.

  6. Identify the requesting site. Under Site Search, type at least two characters of the Site Name to search, and press Select on the right row. If the site is not on file and your site allows it, choose + Add new organization "…"; a New card confirms it will be created as a new organization when this order is saved. Set Priority (Routine, STAT (Urgent), ASAP or Timed). Department / Ward / Unit reads Select facility first and is disabled until then. Tick Remember this site and requester for my next order before a run of orders from one clinic.

    Figure 5. Site Search with one match and its Select button.

  7. Identify the provider. Under Provider Search, enter a name or phone number and press Search, then Select the right row. The provider shows as a Selected card with Edit details and Clear. If nobody matches, + Add new provider "…" splits the name into First Name and Last Name and adds a Title list (Doctor, Professor, Sister and others); the provider is created when the order is saved.

    Provider results show the provider's title with the name, for example Wari, Dr John.

    Figure 6. A provider found and selected.

  8. Choose a program, if your site uses them. According to its help text, selecting a Program displays that program's own Additional Order Information fields below it.

  9. Add clinical information (optional). Provisional Diagnosis is a working diagnosis that guides test selection and is not recorded as a confirmed diagnosis. Payment Status (Normal cash, Normal insurance, Reduced cash or Reduced insurance payment), Order Date (pre-filled with today), Next Visit Date and Sampling Performed At complete the section.

  10. Add at least one sample type, and its tests if known. Choose a Sample Type. Its Order Panels and Order Tests lists then appear, with a filter box and a count of the tests available; ticked tests show as tags above the list. Add Sample adds another specimen; Remove Sample takes one away.

    The section's help text sets the rule: Tests can wait: Save and exit keeps the order without them. Save and next needs at least one test on every sample.

    Figure 7. Serum chosen as Sample 1, with Creatinine, GPT/ALAT and GOT/ASAT ticked. The help text under Sample states when tests are needed.

  11. Save. Until the order has what it needs, a To continue to Prepare Samples list above the buttons names what is missing, and the footer says how many items are needed:

    • With no patient or no sample type (Select or create the patient, Add at least one sample type), both Save and exit and Save and next are disabled.

    • With a sample type but no tests on it, the list reads, for example, Sample 1: choose at least one test. Save and exit is enabled, so you can keep the order and add tests later. Save and next stays disabled.

    When the list is empty:

    • Save and next saves the order and opens Prepare Samples. Enter Order then shows as Done and the order status becomes Entered.

    • Save and exit saves the order and returns to the Order Dashboard with the order highlighted.

    • Discard is also offered, in red, to the left of the save buttons.

    Figure 8. The foot of Enter Order with Serum chosen but no tests ticked: Sample 1: choose at least one test. Save and exit is enabled and Save and next is disabled.

Attachments takes up to 5 files, 10 MB each, as PDF, JPG, PNG or TIFF. On a new order the section says Save the order to add attachments.

Continue or cancel an order from the Order Dashboard

Main menu → Order → Add Clinical Order → Dashboard lists clinical orders with Lab Number, Patient, Facility, Priority, Status, Progress, Last Updated and Action. Above the table are a lab number search, a status filter, a priority filter and a From / To date range, with New Order at the top right.

  • Unfinished orders carry Continue and Cancel order in the Action column; orders that are ready for testing or cancelled carry Open.

  • Cancel order opens a confirmation: Its tests are cancelled and its samples are voided. Nothing is deleted. Choose a Reason for cancelling (Registered in the wrong domain, Duplicate order, Request withdrawn or Other); the Cancel order button stays disabled until you do. Stay closes the dialog without cancelling.

  • A cancelled order leaves the default All Statuses view. Choose Cancelled in the status filter to see it.

  • Scanning or typing a lab number into the dashboard's Scan barcode or enter lab number opens that order. An order that is ready for testing opens on Enter Order marked This order is in read-only mode, with an Edit button.

Figure 9. Cancelling an order from the dashboard, with Duplicate order chosen as the reason.

Order statuses on the dashboard rows are Entered, Samples prepared, Ready for testing and Cancelled. The status filter uses different names: In Progress, Awaiting sample check, Completed, Has referred tests, Referred Out and Cancelled.

Field reference

Field

Notes

Lab Number

Required. Filled in when the screen opens; Generate Lab Number is beside it.

External quality assessment (EQA) sample

Checkbox. Shown when EQA is enabled for the site.

Patient

Required. Search for Patient or New Patient. A new patient is created only when the order is saved. Create patient checks for possible matches first.

Required By

Optional date under Requester.

Site Name

Marked required. Type 2 or more characters to search. A new organization is created when the order is saved.

Priority

Routine (default), STAT (Urgent), ASAP, Timed.

Department / Ward / Unit

Disabled until a facility is selected.

Provider

Search by name or phone, or add new. Results show the title with the name. A new provider has Title, First Name, Last Name, Phone, Provider Email.

Program

Optional. The help text says it displays the program's own fields.

Provisional Diagnosis

Optional. Not recorded as a confirmed diagnosis.

Payment Status

Optional. Shown when payment tracking is on.

Order Date / Next Visit Date

Order Date pre-filled with today.

Sampling Performed At

Visit-point code: B1, J0, J15, M1, M3, M6, M12, Other.

Sample Type

At least one is required to save. Panels and tests appear once chosen.

Order Panels / Order Tests

Save and exit keeps the order without them. Save and next needs at least one test on every sample.

Attachments

Up to 5 files. The section asks you to save the order first.

Tips

  • A misspelled name finds nobody, because search matches names exactly or by their first letters. Search on the first few letters of the surname before creating a new patient; Create patient also warns about likely duplicates.

  • Opening Enter Order uses up a lab number even if you leave without saving. On the reference site the number issued to an abandoned screen was skipped, and no order for it appeared on the dashboard.

  • Field labels and available fields vary by site. Check Order Entry Configuration before concluding the manual is wrong.

  • The Order Date field and the Date of Birth field can show dates in different orders (month first and day first) on the same screen: on the reference site Order Date read 10/07/2026 for 7 October while Date of Birth asked for dd/mm/yyyy. Read the placeholder before typing.

Not yet available

  • A record of lab numbers issued but never used.
