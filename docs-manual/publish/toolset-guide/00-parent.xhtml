Who this is for. Taib, Jen, and anyone on the docs and training team who helps keep the OpenELIS Global user manual, its translations, screenshots and website current. You do not need to be a developer. A few one-time setup steps install software, and we say clearly when to ask for help. Day to day, you ask Claude in plain English.

What this toolset does

OpenELIS changes every release, and the manual has to keep up. With the toolset installed, you can ask Claude to:

  • write or update a user manual page: Claude checks the live software, captures the screenshots, writes the page in our house style, and publishes it to Confluence;
  • capture screenshots and walkthrough videos of the real software for the manual, the website or a review;
  • run the freshness check, which finds manual pages whose screens changed and translated pages that are behind their English page;
  • keep the French and Indonesian manuals (Spanish next) in step with the English one;
  • keep the Documentation triage bench current: the one list of what to fix next.

The one rule

Document only what the software does today, on a live test site. Many OpenELIS features are designed but not built yet, or built differently from the design. A step goes into the manual only after someone has done it on the live site. If you cannot reproduce a step, say so; do not publish it.
