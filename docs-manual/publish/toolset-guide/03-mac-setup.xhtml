Goal of this page. Get the two working folders onto your Mac once: the capture harness (which signs in to the live software and takes the screenshots, and runs the freshness check) and the docs tooling (drift contracts, the Confluence publisher, the translation kit). Claude does almost all of it; you approve a few installs.

Screenshots for a page can also be taken by Claude in its own cloud workspace, with nothing on your Mac. The Mac setup is still needed for the freshness check and for publishing, because your publishing key lives only on your Mac.

The whole setup is one conversation

Start a new chat in the OpenELIS User Manual project and paste this in:

text

Claude will:

  1. Clone the capture harness to ~/Documents/OpenELIS QA.
  2. Install Node (the engine the harness runs on) if it is missing, and the automation browser.
  3. Save a login to the test site, so captures can sign in on their own.
  4. Clone the docs tooling to ~/Documents/openelis-docs and link it into the harness folder (the freshness check runs from there).
  5. Take a test screenshot and show it to you.

The publishing key (only if you will publish)

When Claude publishes a page with its figures, a script on your Mac uses a small key file at ~/.openelis/confluence.env. Ask Casey to help you create it once. It holds your Confluence access: never paste it into a chat, never share it, never put it in GitHub. Claude never needs to see it, and the plugin stops Claude from printing it. If you only capture and draft, and Casey publishes, skip this.

The key needs Confluence permissions, not only Jira ones. A key made for Jira can read pages but every upload of a figure fails; Part 7 explains how to spot that.

Good to know

  • Which site. Manual pages are checked on testing.openelis-global.org. Quality pages (EQA, QC) and environmental and vector sample types are checked on pngtest.openelis-global.org, a test server where Claude may change and add data. indonesiademo is no longer used.
  • Long jobs run in the background. A full capture or the freshness check can take up to 30 minutes; Claude starts it, checks on it, and tells you when it is done.
  • Media stays out of GitHub. Screenshots stay in the harness folder until they are put on a page.
