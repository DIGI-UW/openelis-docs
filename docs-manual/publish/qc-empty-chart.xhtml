Why is my QC chart empty?

At a glance

PurposeWork out why an analyzer is missing from the QC Dashboard, or why its control results are not being evaluated, by checking the five things that must all be true.
You'll end up withThe one link in the chain that is broken, and the page of this manual that fixes it.
Who does thisWhoever notices the gap — usually the analyst reviewing QC or the supervisor. Access is set by user permissions and can be configured by your administrator.
Before you startThe name of the analyzer and the test you expected to see, and the lot number of the control you ran.
WhereMain menu → Analyzers → Analyzers List, and Analyzers → Quality Control → QC Dashboard, Control Lots, Rule Configuration

By design, a failure in QC processing does not stop the analyzer's results from importing, so if any link in the chain is missing the only symptom is that the analyzer does not appear on the QC Dashboard and no violation is ever raised. That silence is the diagnosis: work down this list in order and stop at the first check that fails.

The import behaviour described here is as designed and has not yet been verified on a live instance. Confirm before publishing.

{{IMG:01-qc-dashboard-empty.png}}

Figure 1. The QC Dashboard reading No instruments found: the symptom this page diagnoses.

Check 1 — Is the analyzer connected to OpenELIS?

Open Analyzers → Analyzers List. The analyzer must be listed, and its connection must be complete: an analyzer still at Status Setup or flagged Plugin Missing can hold lots and rules but is not yet delivering results. Control results only reach OpenELIS through an analyzer's electronic connection. Fix: add the analyzer or complete its setup (see the analyzer integration pages of this manual).

{{IMG:02-analyzers-list.png}}

Figure 2. The Analyzers List; this analyzer is still at Status Setup with a Plugin Missing flag.

Check 2 — Are control results reaching OpenELIS at all?

Open Analyzers → Error Dashboard and look for rejected or unmatched messages from the analyzer around the time the controls were run. If the analyzer's patient results are arriving but its control results are not, the analyzer's mapping does not recognise the control samples as controls.

This check has not yet been verified on a live instance: the test instance had no analyzer traffic, so the Error Dashboard's contents for a control run could not be observed. Confirm what a mis-identified control looks like there before publishing.

Check 3 — Is there an Active control lot for this exact analyzer and test?

Open Analyzers → Quality Control → Control Lots and set the Status filter to Active. There must be a lot whose Lot Number matches the material you ran, and which was registered against the same analyzer and test. A lot registered against a different analyzer or test, or one that is no longer Active, is not the lot the results are matched to. Fix: register the lot — see Receive and activate a control lot.

The matching behaviour described here is as designed; it could not be exercised on the test instance because no control results were available. Confirm before publishing.

{{IMG:03-control-lots-list.png}}

Figure 3. The Control Lots list; the lot for the analyzer and test must be present and Active.

Check 4 — Does the lot's identifier match what the analyzer sends?

The Lot Number on the Control Lots page must be the same identifier the analyzer transmits with the control result. A lot typed with a different prefix, spacing or level suffix from the analyzer's own value will not match. Compare the Lot Number field with the analyzer's printout.

This check describes the matching rule as designed. How a mismatch is surfaced in the user interface has not yet been verified on a live instance. Confirm before publishing.

Check 5 — Are Westgard rules enabled for the pair?

Open Analyzers → Quality Control → Rule Configuration. The analyzer and test must appear under Configured Rule Sets with an Enabled Rules count greater than 0/8, and at least one enabled rule should have Rejection severity. If the pair is missing, no lot has been saved for it (go back to Check 3). If rules are all off, open Options → Edit and enable them — see Set up QC for an instrument.

{{IMG:04-rule-configuration-list.png}}

Figure 4. Rule Configuration; the pair must be listed with rules enabled.

Tips

  • The QC Dashboard lists an analyzer only after at least one control result has been matched to an active lot. A newly set-up analyzer with a lot and rules but no run yet is correctly absent.
  • Choose Refresh on the QC Dashboard after the analyzer has finished sending; Last Updated shows when the page last reloaded.
  • Known defect (3.2.2.0): the test name shown on Rule Configuration may differ from the one chosen on the lot. Use the analyzer name to identify the pair.
  • Known defect (3.2.2.0): an existing lot cannot be edited or set Inactive (Failed to save control lot). If a lot was registered wrongly, register a corrected lot.
