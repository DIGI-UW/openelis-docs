How-to · Lab administrators and lab IT

Status: draft, unverified against 3.2.2.0. Captured from analyzers.openelis-global.org on 15 September 2026.

At a glance

Purpose

Connect a laboratory analyzer so its results flow into OpenELIS.

You'll end up with

An active analyzer whose results arrive against the right tests.

Who does this

Lab administrators, usually with lab IT for the connection details. Access is set by user permissions and can be configured by your administrator.

Before you start

The Analyzer Bridge must be running and reachable. You also need the instrument's model, the lab units it serves, and its connection details — a watched directory for file-based instruments, or a host and port for ASTM and HL7.

Where

Main menu → Analyzers → Analyzers List → Add Analyzer

The Analyzer Bridge is a prerequisite

Nothing on these screens works without the Bridge. OpenELIS holds the lab-facing setup — which analyzer exists, which lab units it serves, how its tests map to yours — while the Analyzer Bridge owns the instrument profiles, the connections and the parsing, and delivers normalised results back to OpenELIS.

If the Bridge is unreachable you will see "Analyzer types could not be loaded. Check the Analyzer Bridge connection", an empty analyzer type list, and a Create New Analyzer Type button that does nothing. That is not a fault in OpenELIS — it means the Bridge is not answering. See OGC-1214.

Analyzer types come before analyzers

An analyzer type is the reusable setup behind an analyzer: the protocol, the test and result mappings, and the rules for recognising control material. Several identical instruments share one type.

Some types ship with OpenELIS and the rest you create. Shipped types carry a revision number. To adapt one, Duplicate Profile creates a Site-created type recorded as derived from the shipped revision it came from — so the lineage stays visible.

Deactivate types rather than deleting them. The screen says so directly: deactivating keeps the history.

The Results mapped ratio on this list and the one inside the mapping editor can disagree — a type showing 10/16 here read 11/17 in the editor. The two counts appear to be calculated differently; treat the editor as authoritative when working on mappings.

Set up an analyzer

Add Analyzer opens a three-step wizard: Instrument → Verify → Connect.

Step 1 — Instrument

  • Analyzer type — search and select. The list filters as you type, and each option reads name · manufacturer · protocol · revision.

  • Analyzer name — what the lab will call this particular instrument. Use something that distinguishes it from its siblings; sites commonly include a serial number.

  • Lab units — a multi-select of the units this analyzer serves.

  • Instrument not listed? covers an instrument with no matching type.

All three fields are required — the form reports Select an analyzer type, Enter an analyzer name and Select at least one lab unit if you continue without them.

Step 1 of the wizard, with the three required fields flagged.

Then Continue to Verify.

panel_c1

The analyzer record is created at this point, before you reach Connect. It appears in the list with status Setup. Closing or cancelling the wizard afterwards does not remove it — use the row's Deactivate action if you started one by mistake.

Step 2 — Verify

Step 1 collapses to a summary with an Edit link, and the type's mappings are presented for review:

  • Tests mapped — for example 1 of 1 tests ready

  • Results mapped — for example 0 of 0 result values ready

  • Control result recognition — how the analyzer's quality-control material is identified rather than treated as a patient result. Rule-based, and the rules are listed. On the shipped FluoroCycler type they were: control task equals Positive, Negative or Standard, and specimen ID starting with C+ or C-.

  • Current confirmation — who confirmed these mappings and when

Review mappings in Analyzer Types opens the type itself if something needs changing. This step reviews the type, so a change here affects every analyzer sharing it.

Step 2 presents the analyzer type mappings and control-recognition rules for review.

Then Continue to Connect.

Step 3 — Connect

The fields here depend on the protocol. For a FILE analyzer:

  • Data flow — for example Results only

  • Directory — required; where the instrument writes its output

  • File pattern — the file name pattern the Bridge watches

  • Test connection — checks the Bridge can reach it

ASTM and HL7 analyzers ask for transport details instead — each saved connection owns its own port, and that port has to be published by the Bridge.

Activation readiness reports whether the setup can be activated, and says so plainly when it cannot: "Analyzer setup is not ready to activate."

Finish with Finish and activate, or Save and finish later to leave it in Setup.

Held results

A banner appears on the Analyzers list when an analyzer has held results: "Map unknown tests or result values before using these results clinically", with a Review held results action.

This is a safety mechanism, not a nuisance. When results arrive carrying a test or result value OpenELIS cannot map, they are held rather than filed against the wrong test.

See Map analyzer codes, resolve held results, and run QC for how to work through them.

Managing an existing analyzer

The row Actions (⋮) menu offers:

  • View results — what this analyzer has sent

  • Edit setup — reopen the wizard

  • Configure connection — the Connect step on its own

  • Quality Control — see Analyzers → Quality Control

  • Deactivate — stops new runtime use. The confirmation is explicit that configuration and history are retained and the analyzer can be reactivated later.

Tips

  • If the analyzer type list is empty, the Bridge is unreachable. Nothing else on these screens will work until that is fixed.

  • The analyzer is saved at step 1. Cancelling later leaves a record in Setup.

  • Verify reviews the shared type. Changing mappings there affects every analyzer using it — duplicate the type instead if only one instrument should behave differently.

  • Name instruments so siblings are distinguishable; several analyzers commonly share one type.

  • Held results mean unmapped tests or values. Map them rather than working around the hold.

Not yet documented

View results, the Instrument not listed? path, and creating an analyzer type from scratch with Create New Analyzer Type. Connection details for ASTM and HL7 analyzers have not been observed — only FILE.

Installing and configuring the Analyzer Bridge itself is a separate task for lab IT; see the openelis-analyzer-bridge repository.
