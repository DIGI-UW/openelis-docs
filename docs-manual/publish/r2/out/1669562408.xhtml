Status: draft for review. Re-checked on pngtest.openelis-global.org (OpenELIS 3.3.0-SNAPSHOT, English) on 12 and 13 October 2026 with a new CD4 count scheme, six provincial hospital laboratories and a three-level panel, run end to end from scheme to closed cycle. Steps first written on 3.2.2.0 in September and not repeated are marked. The companion page for laboratories that receive panels is EQA participant: take part in a proficiency testing scheme.

At a glance

Purpose

Run an external quality assessment (EQA) scheme for other laboratories: define the scheme, enrol laboratories, build and ship a panel, score what comes back, publish results and follow up failures.

You'll end up with

A closed cycle with every participant scored, a performance report per laboratory, and a follow-up record for each unacceptable result.

Who does this

QA officers or scheme coordinators. Access is set by user permissions and can be configured by your administrator.

Before you start

The participating laboratories set up as organizations in OpenELIS, the panel material with its lot, targets and acceptance limits, and courier details for each box.

Where

Main menu → Quality Assurance → EQA → EQA Management → Schemes and Participants; EQA Provider (cycles); Participant Follow-Up; In-House Blinding

How a provider cycle runs

A scheme is set up once. Each round is a cycle, and a cycle moves through a fixed sequence that the system enforces: Prep in progress → Ready to ship → Shipped → Delivered → Submissions open → Scored → Closed. Each state gates the next, so a panel cannot be shipped before prep passes, and a cycle cannot be closed while a follow-up is open.

The work happens on four screens: Schemes (titled Scheme Administration) to define the scheme, Participants to enrol laboratories, the EQA Provider board and its cycle workbench to run each round, and Participant Follow-Up for laboratories that failed.

1. Create the scheme

  1. Go to Main menu → Quality Assurance → EQA → EQA Management → Schemes. The page is titled Scheme Administration. Tiles count active schemes and enrolled participants, and the list shows every scheme with its provider, type, enrolled participant count and status.

    Figure 1. Scheme Administration with three schemes.

  2. Select Add Scheme. Complete Scheme Name, Scheme type, Provider and Description, then pick the tests under Assigned Tests. Choose Regional PT when a national or regional laboratory runs the scheme, as here. The helper under Assigned Tests says result intake offers exactly these tests, on the results grid and in its CSV import.

    Figure 2. Add New EQA Scheme, with the scheme type and provider (September capture).

  3. Scroll down and set the two switches. Record the analyst on every result feeds Analyst Competency. Hold each cycle for review before submitting (shown off as Submit automatically) applies to laboratories that take part in the scheme. Select Add Scheme. The new scheme appears in the list as Active with 0 enrolled participants.

    Figure 3. One assigned test and the two switches at the foot of the form.

Treat the scheme type as permanent. Results are read against the type the cycle ran under. The form does not stop you changing it later, so if you chose the wrong type and a cycle has run, create a new scheme instead.

2. Enrol the participating laboratories

A scheme appears on the EQA Provider board only once at least one laboratory is actively enrolled in it. If the board looks empty, check enrolments first.

  1. Go to EQA Management → Participants. Pick the scheme in Select scheme; nothing is listed until you do. Choose a laboratory from Select an organisation and select Enroll. The page confirms Enrollment successful, and an enrolled laboratory leaves the organisation list.

    Figure 4. Participants, with a scheme selected and a laboratory chosen (September capture).

  2. Repeat for each laboratory. Each one appears in the table with its code, enrolment date and status. The status filter shows Active, Suspended or Withdrawn enrolments, and the icons under Actions pause or withdraw a laboratory. A withdrawn enrolment stays on record.

    Figure 5. Six provincial hospital laboratories enrolled and Active.

3. Create a cycle

  1. Go to EQA → EQA Provider. The board, EQA schemes we provide, shows tiles for active schemes, open cycles, enrolled participants and open follow-ups, and one row per scheme with New cycle and Performance. Select New cycle on your scheme.

    Figure 6. The provider board (September capture).

  2. Cycle. Enter the Cycle name. Leave Cycle number blank to take the next unused number. Pick the Distribution date and Submission deadline from the calendar. Typing a date does nothing and leaves Next disabled; click the field and pick the day.

    Figure 7. Wizard step 1, Cycle (September capture).

  3. Panel. Enter the Panel name, Material source and Lot number. Vendor-supplied material adds Vendor name, Vendor lot and Vendor certificate reference. Add one row per sample (Add sample) with its sample code, test, Target value, unit and Acceptance low and Acceptance high; participants are scored against these limits, sample by sample. Set Storage temperature, which becomes each box's temperature requirement, and Material expiry.

    Figure 8. Wizard step 2, Panel: three CD4 levels of the same test, each with its own target and acceptance limits.

    A target value is sealed and encrypted at rest. Leave it blank when the target is known only at scoring time. The sample code fields are narrow: the codes here are CD4-26-4-01, -02 and -03, as the pack list shows. Pick the test carefully: see Known issues.

  4. Participants. Choose which enrolled laboratories take part. Only enrolled laboratories are offered, and only those chosen here count towards the prep gate.

    Figure 9. Wizard step 3, all six laboratories selected (September capture).

  5. Distribution. Choose FHIR, CSV export or Mixed. The cycle on this page used CSV export.

    Figure 10. Wizard step 4, Distribution method (September capture).

  6. Confirmation. Check the summary and select Create cycle and begin prep. The cycle opens in its workbench in the Prep in progress state.

    Figure 11. Wizard step 5, the summary before the cycle is created (September capture).

4. Prepare the panel

The workbench has four tabs: Prep, Shipments, Receipts & scoring and Report comments. Cycle history at the top lists every state change, what triggered it (for example Manual, First shipment sent, Scores recorded), who made it and why.

  1. On Prep, the Ready-to-ship gate lists what is still missing, for example a panel that has not passed homogeneity QC or does not have enough aliquots. The panel card shows the arithmetic and the recommended reserve, max(10% of participants, 5). Record Aliquots produced, Aliquots reserved, tick Homogeneity QC passed, add QC notes and select Save prep record.

    Figure 12. Prep before anything is recorded: the gate lists two blockers (September capture).

  2. The gate and the arithmetic recompute when you save, not while you type. After saving, the gate reads All prep requirements met and Mark cycle ready to ship becomes available.

    Figure 13. Prep saved: 3 samples x 6 participants + 5 in reserve = 23 aliquots needed, 24 produced (September capture).

  3. Select Mark cycle ready to ship. The cycle moves to Ready to ship and the page points you to the Shipments tab.

    Figure 14. The cycle cleared to ship (September capture).

5. Ship the panels

  1. Open Shipments. There is one row per laboratory, each with its own box code and the status Ready to Send. Enter the Courier, Tracking number and Expected delivery (calendar only), then select Save on that row. The saved values stay in the row. Save each row before you edit the next.

    Figure 15. Shipments, with courier, tracking and expected delivery saved on every row.

  2. Print the documents that travel with each box. Pack list downloads a shipping manifest with the box, destination, state, temperature requirement and the panel samples; target values are never printed on it. Label downloads the box label with destination, temperature requirement and sample count.

    Figure 16. The shipping manifest for one box.

    Figure 17. The box label.

  3. Tick Select all pending (or individual rows). The button becomes Mark 6 shipped.

    Figure 18. All six boxes selected.

    Select Mark 6 shipped. The first dispatch moves the cycle to Shipped. Shipped rows show Sent and the ship date, and their fields become read-only.

    Figure 19. Six shipments dispatched; the cycle is Shipped.

6. Track receipt and send repeats

  1. Open Receipts & scoring. Each laboratory shows a status (In transit, Delivered, Overdue), the expected and received dates, the receipt condition and its scores. Overdue means two business days past the expected delivery. When a laboratory confirms receipt by phone or email, select Mark received; it acts at once.

    Figure 20. The first delivery recorded (September capture).

  2. If a box is lost, delayed or damaged, select Send repeat. The dialog takes the repeat's own Courier, Tracking number and Expected delivery, and an Override note. The repeat comes out of the panel's reserve; if the reserve cannot cover it, the note is required as a written justification.

    Figure 21. Send a repeat panel for a box that arrived warm.

    The row is marked Repeat shipment and is In transit again, with Mark received. On Shipments the repeat box appears with an -R1 suffix (for example EQA-C1-32-R1).

    Figure 22. The repeat in transit.

  3. Submissions open on their own once every participant holds its panel; you do not need to open them by hand. Once submissions are open, Score cycle appears.

    Figure 23. All six delivered; submissions opened without any action (September capture).

    If one box is holding up the rest, use Open submissions, which appears once any laboratory has its panel. The dialog, Open submissions with undelivered panels, says that laboratories without their panel stay on the roster as late and that this is a recorded manual override. Enter the Reason and select Open submissions. The late laboratory's row stays In transit and keeps Mark received. (September capture; not repeated on 3.3.0.)

    Figure 24. Opening submissions while one box is still in transit.

    The override is kept in Cycle history with its reason.

    Figure 25. Cycle history, with the reason recorded against the override.

7. Record results and score the cycle

Laboratories that run OpenELIS return results through the FHIR store. For a laboratory that phones, emails or sends a file, key the results yourself.

  1. Select Enter results on the laboratory's row. The dialog has one row per panel sample, labelled with the test and the sample code. Key each value as reported (a number, or a word such as Reactive) and select Save results. Saving overwrites what is on file for that sample.

    Figure 26. Results from one laboratory, one row per panel sample.

  2. If the laboratory sent its export bundle, paste it into Or paste the participant's export bundle (CSV) and select Import CSV. The file needs analyte_name and result_value columns. The imported values fill the grid; select Save results. (September capture; CSV import was not repeated on a multi-sample panel.)

    Figure 27. After Import CSV: "1 values imported" and the value filled into the grid.

  3. The Scores column stays empty until the cycle is scored. When results are in, select Score cycle. Where the panel carries targets and acceptance limits, each result is judged against its own sample's limits. A cycle whose panel has no targets is scored against its peers and needs at least five reported results. After scoring, the cycle is Scored and the Scores column shows, for example, 1 unacceptable of 3. Unacceptable laboratories go straight into the follow-up register.

    Figure 28. The cycle scored.

    Figure 29. Scores per laboratory: Modilon has one unacceptable result of three.

8. Publish results and reports

  1. For each laboratory, Report PDF downloads its performance report: scheme, type, cycle, planned period and participant, an overall and a section summary, and a scoring detail line per sample with the reported value, target, difference, z-score and Performance. The verdict comes from the acceptance limits: 1395 is above the 1280 limit, so it is Unacceptable although its z-score against the other laboratories is 1.92. Scores CSV downloads the same rows as a file, with the sample code on each.

    Figure 30. The performance report for one laboratory.

  2. For a cycle distributed by CSV export, send each laboratory its Report PDF and Scores CSV. No Send scores action is offered on such a cycle. Sending scores through the FHIR store for a FHIR cycle was not checked on 3.3.0.

  3. On Report comments, pick one or more pre-approved comments and select Add to report. Only comments from the library can be printed; the wording is maintained under Administration → Dictionary Management. (September capture.)

    Figure 31. A library comment added to the cycle's report.

9. Follow up failures and close the cycle

  1. Close cycle asks for a reason and is refused while a follow-up is open or a missed-deadline result is still waiting on an answer.

    Figure 32. Closing refused while one follow-up is open (September capture).

  2. Select Follow-up register (or go to EQA → Participant Follow-Up). It lists the laboratories in your schemes that returned unacceptable results. This register is correspondence with another laboratory; it never opens a non-conformity in your own laboratory's register. Expand a row with the arrow at its end to see the test, the sample code, the reported value, the target and the z-score.

    Figure 33. A follow-up expanded, with its actions.

  3. New entries start as Notified. An expanded entry offers Notify lab, Record response, Investigate, Resolve, Remove from scheme and Flag for repeat.

    Record response asks What the laboratory said: the root cause the laboratory found and the corrective action it took. Select Confirm. The entry moves to Response received, the response date is filled in, and the laboratory's response is shown under the result.

    Figure 34. Recording the laboratory's response.

    Figure 35. The entry with the response recorded.

    Investigate moves the entry to Under investigation.

    Notify lab emails the laboratory's contact: in 3.3.0 that is the Email under Contact on the organization's record (see Admin: Manage organizations (3.3.0); OGC-1265). When no contact email is on file, it downloads the notification as a CSV for you to send by hand, and a message says so. Sending by email was not verified.

    Figure 36. Notify lab with no email on file: the notification is downloaded instead (September capture).

    Flag for repeat sends the laboratory a fresh panel so it can test again. It opens the same Send a repeat panel dialog as the workbench. The entry stays Notified and the laboratory's row on the workbench is marked Repeat shipment. (September capture.)

    Figure 37. Flag for repeat.

    Figure 38. The repeat in transit on the workbench.

    Remove from scheme withdraws the laboratory from the scheme. Record what was agreed with the laboratory in Notes and select Confirm. On EQA Management → Participants the laboratory then reads Withdrawn, and the next cycle's Participants step no longer offers it. (September capture, when the action was labelled Remove from programme.)

    Figure 39. Removing a laboratory from the scheme, with the agreement recorded.

    Figure 40. The entry marked as removed.

    Figure 41. The removed laboratory's enrolment, now Withdrawn.

  4. Select Resolve, record what was agreed with the laboratory in Notes, and select Confirm. The notes are kept against the register entry for accreditation trace.

    Figure 42. Resolving a follow-up with the agreed corrective action (September capture).

    Figure 43. The follow-up resolved (September capture).

  5. Return to the workbench, open Receipts & scoring and select Close cycle, giving a Reason. The dialog warns that a closed cycle is final and no further verdicts are recorded against it. A closed cycle keeps only Scores CSV and Report PDF on each row.

    Figure 44. The cycle closed.

10. Review participant performance

  1. On the provider board, Performance on a scheme's row opens Participant performance for that scheme, named in the title: each laboratory's province, enrolment, pass rate over its last four scored cycles, its most recent verdict and its open follow-ups. Expand a row to see the cycles behind the rate.

    Figure 45. Participant performance for the CD4 scheme.

11. Run an in-house blinded panel

In-House Blinding is for testing your own analysts with your own material: the panel is blinded, dealt to named analysts as ordinary-looking orders, and scored against sealed targets on the unblind date. It needs no provider, no enrolment and no shipping. This section was driven end to end on 3.2.2.0 in September. On 3.3.0 only the scheme and the first two wizard steps were re-checked.

  1. Create a scheme whose Scheme type is In-house (as in step 2 above). The helper says in-house schemes are run by this laboratory and need no provider, and the Provider field disappears. Add the tests and turn on Record the analyst on every result, which Analyst Competency needs. In-house is the only type that appears in In-House Blinding.

    Figure 46. An in-house haematology scheme with three assigned tests.

  2. Go to EQA → In-House Blinding and select Launch blinding wizard. Scheme & cycle: choose the In-house scheme, enter the Cycle name, and set the Planned start date and Unblind date (submission deadline). Next stays disabled until the scheme, name and both dates are filled in.

    Figure 47. Wizard step 1, Scheme & cycle.

  3. Samples & prep. Add one row per sample (Add sample) with its Test, Target value, Unit, Range low and Range high. The page states that target values are sealed when the wizard finishes and are never stored in clear text.

    Figure 48. Three samples, one test each, with targets and acceptable ranges.

    Under Prep & aliquoting details, record the Source, Lot number, Aliquots produced, Storage temperature, Expiration date, Homogeneity QC passed and Homogeneity QC notes.

    Figure 49. Prep and aliquoting details for the pooled material.

  4. Analysts. Under Scheme analysts, choose the OpenELIS user accounts that join the scheme's roster, then the Assignment mode: Round-robin, Identical set or Manual per-sample assignment. The page works out the number of blinded aliquots and lists each sample with its analyst.

    Figure 50. Three bench analysts on an identical set.

  5. Confirm & seal. Check the summary. After sealing, revealing a target takes the unblind privilege and is recorded in the audit trail, and the panel cannot be edited. Select Seal panel & distribute.

    Figure 51. The summary before sealing.

  6. The confirmation lists the blind codes (for example IH-3-01 to IH-3-09), which the blinded orders carry as their sample IDs, and the unblind date. Print label sheet, Open My Cycles and Open the Workplan are offered.

    Figure 52. Panel sealed and distributed, with its nine blind codes.

  7. Analysts enter results on the Results page by blind code, and the results go through Validation like any other.

    Figure 53. A blinded order on the Results page (3.2.2.0 Results page).

  8. Back on In-House Blinding, the panel row shows its sample count, Sealed targets, the status and the unblind date. Panels unblind on their unblind date. To unblind early, select Unblind now on the row. It acts at once, with no confirmation.

    Figure 54. The panel in testing.

  9. Unblinding scores the results against the sealed targets. A result outside its range goes to This Lab's Follow-Up as an in-house failure, and every scored result counts on Analyst Competency; both are described on the participant page.

    Figure 55. The panel unblinded and scored.

Known issues in 3.3.0-SNAPSHOT

  • Test pickers offer the whole catalogue. The cycle wizard's Panel step and the blinding wizard's Samples step list about 790 tests rather than the scheme's assigned tests, and some tests appear twice under the same name (for example two "CD4 Absolute count (mm3)(Whole Blood)"). Pick the one that matches the scheme: result intake offers only the scheme's own test. (OGC-1251 is marked Done; the pngtest build checked on 13 October still showed this.)

  • Dates in the cycle wizard must be picked from the calendar; typed dates are discarded and Next stays disabled.

  • The performance report's Laboratory row shows a dash; the participant is named on the Participant row below it. (OGC-1258)

  • On Participants, the Organisation Code column shows the organization's short name, and the page subtitle still says "EQA programs". Still seen on testing and pngtest on 13 October, although OGC-1261 is closed. (OGC-1261)

  • The provider board's Discipline column shows a dash.

  • Not re-checked on 3.3.0, although OGC-1245 was closed on 13 October: the In-House Blinding analyst assignments and their credit on Analyst Competency (OGC-1245, OGC-1249), Send scores on a FHIR cycle, and CSV import on a multi-sample panel.

Fixed since the 3.2.2.0 draft and checked on 3.3.0: panels with several samples of one test are entered and scored per sample (OGC-1243); Expected delivery stays after Save (OGC-1259); Scores stay empty until scoring (OGC-1253); Send repeat has courier, tracking and delivery fields (OGC-1254); Record response takes text (OGC-1256); closed and scored cycles no longer offer result actions (OGC-1248); the pack list and Cycle history show readable states and triggers (OGC-1258, partly fixed: see the Laboratory row issue above); the workbench banner and Participant performance title are right (OGC-1262). The System Settings tab described in the 3.2.2.0 draft is no longer on Scheme Administration (OGC-1247).

Not covered here

Taking part in someone else's scheme, including This Lab's Follow-Up and Analyst Competency, is on EQA participant: take part in a proficiency testing scheme.
