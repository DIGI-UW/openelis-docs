Overview

The Notifications page has four tabs. Triggers lists the events that can send a notice and who receives it. Templates holds the subject and message for each event. Channels connects Email, SMS and WhatsApp; as the tab says, they are set up here once and used by every message the laboratory sends. Delivery Settings holds lab-wide rules such as retries, the lab contact line and the default country code for phone numbers.

Which tests send a notice when their result is released is chosen per test on a separate page; see Admin: Configure test notifications. Every message sent, and every failed attempt, is listed on Sent Messages: check and resend deliveries.

Step 1: Choose the events that send a notice

Go to Main menu → Admin → Notifications. The page opens on Triggers, under Active Triggers. Each row is one event: Referral Out (a sample is referred to an external laboratory), Subcontract Dispatched (a sample has been physically dispatched to the receiving laboratory), Sample re-collection (an order is marked for re-collection and a replacement order is created), Referral result rejected (a result returned by the reference laboratory is rejected and the sample must be collected again) and Referral nudge (a referral is overdue and a nudge is requested). Each row shows its Event Code.

For each event you want:

  1. Turn on Enabled. Every trigger is off until you turn it on; the row says it defaults off and must be enabled explicitly.
  2. Tick the Channels to use: Email, SMS and/or WhatsApp.
  3. Tick the Recipients: Ordering Provider, Submitting User and/or CoC Contact.

Press Save Configuration, or Cancel to discard your changes. The channel and recipient boxes stay greyed out until the trigger is enabled.

Step 2: Word the messages

Open Templates. Notification Template Configuration has one tab per event: Patient results ready, Referral Out, Subcontract Dispatched, Referral result rejected, Referral nudge and Sample re-collection. Each tab says who receives the message; Patient results ready, for example, goes to the patient or the provider when a configured test's result is released and never names the patient.

  1. Choose the event tab, then the Channel: Email or WhatsApp. Each channel has its own template.
  2. Edit the Subject and Message Body. To add a value from the record, place the cursor and click a field under Available Merge Fields, for example [testName]. The fields offered depend on the event; Referral Out offers the sample number, the receiving laboratory's name, the referred tests, the referral date and the expected return date, among others.
  3. Check the Rendered Preview under the message, which fills the merge fields with example values.
  4. Press Save Template. Reset to Default puts the default wording back.

{{IMG:n02-templates.png}}

Figure 2. The Patient results ready template for Email: Subject [testName] results ready, the message body, the merge fields [testName], [testResult], [accessPassword] and [accessAddress], and the Rendered Preview for Malaria RDT.

Step 3: Check the channels

Open Channels. Each channel, Email, SMS and WhatsApp, shows whether it is set up and its Last successful send, with Send test and Edit. Send test is described on Sent Messages.

{{IMG:n03-channels.png}}

Figure 3. The Channels tab on the test server: Email, SMS and WhatsApp all Not set up, Last successful send: Never.

Step 4: Set up email

Press Edit on the Email row. Leave Active on, and enter the SMTP host, Port, Security (STARTTLS, SSL/TLS or None), the Username and Password of the account to send from, the Sender address and Sender name recipients will see, and an optional Reply-to address. Press Save, then use Send test to check it.

{{IMG:n04-channel-email-edit.png}}

Figure 4. Email being set up with example values: SMTP host smtp.pmgh-lab.example.org, port 587, STARTTLS, sender results@pmgh-lab.example.org and sender name PMGH Laboratory Results. Not saved.

Step 5: Set up SMS

Press Edit on the SMS row. The SMS gateway itself is not set up here: the screen explains that the gateway (BMP or SMPP) keeps its settings in the server properties, and that this row shows whether one is enabled. Leave Active on, enter the Default country code used for phone numbers entered without one, and press Save.

{{IMG:n05-channel-sms-edit.png}}

Figure 5. SMS opened for editing: Active, the note about the gateway settings, and Default country code.

Step 6: Set up WhatsApp

Press Edit on the WhatsApp row. Leave Active on and enter the Account SID, Auth token and Sending number from your WhatsApp provider, and the API address (optional) if your provider gives one. Press Save.

{{IMG:n06-channel-whatsapp-edit.png}}

Figure 6. WhatsApp opened for editing: Active, Account SID, Auth token, Sending number and API address (optional).

Step 7: Set the delivery rules

Open Delivery Settings, lab-wide rules for how reports, alerts and notices are sent:

  • Retry after (minutes, in order): for example 1,5,15, meaning a failed send is tried again after 1, 5 and 15 minutes and then marked Failed.
  • Format for recipients without a password: Masked copy or Protected full report.
  • Wait before sending a new version (minutes).
  • Send partial reports automatically.
  • Lab contact line: phone, email and opening hours, as printed in notices.
  • Where reports are sent from: This lab or Central delivery service. Central delivery service address is greyed out while This lab is chosen.
  • Secure links and Link lifetime (days).
  • Default country code.

{{IMG:n07-delivery-settings.png}}

Figure 7. Delivery Settings with the PMGH Laboratory contact line and default country code +675 entered; retries 1,5,15, Masked copy, 10 minutes before a new version, partial reports sent automatically, reports sent from This lab, secure links off with a 14-day lifetime.

Step 8: Save the delivery rules

Press Save. A Settings saved. message confirms it.

Tips

  • Set up and test a channel before you enable a trigger that uses it. Until then every message on that channel is recorded on Sent Messages as Failed with the reason, for example Email is not set up.
  • Enter the default country code of your country (for example +675 for Papua New Guinea), so phone numbers entered without one still reach the right place.
  • Templates are not translated by OpenELIS. Write each one in the language its recipients read.
  • Keep passwords and tokens to the channel fields. Never put them in a template or the lab contact line, which appear in messages.
  • Referral Out fires once per saved referral: if one order is referred to two laboratories, two notices are sent, as the Triggers tab notes.
  • On the test server the Templates tab showed a note about [expectedReturn] (a Referral Out field) under the Patient results ready merge fields as well.
