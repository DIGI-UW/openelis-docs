How-to · Administrators

At a glance

Purpose

Choose which notifications are sent for each test — to the patient or the provider, by email or SMS.

You'll end up with

Per-test notification channels enabled, so results and updates reach the right people automatically.

Who does this

Administrators. Access is set by user permissions and can be configured by your administrator.

Before you start

Which tests should trigger which notifications. Email and SMS delivery must be configured (see Application Properties).

Where

Main menu → Admin → Test Notification Configuration.

Test Notification Configuration is a per-test grid of the four notification channels — Patient Email, Patient SMS, Provider Email, and Provider SMS. Tick the channels a test should use; open a test's Edit to set its message templates

Step 1 — Find the test

  1. Open Main menu and Admin.

Click admin

  1. Click Test Notification Configuration.

Test notification configuration

panel_c1

The grid lists every test with a checkbox for each channel. Filter with Test names or Select sample type to narrow the list (use Clear Filters to reset).

The Test Notification Configuration grid: each test with Patient Email, Patient SMS, Provider Email, and Provider SMS channels, plus a per-test Edit.

Step 2 — Enable channels and save

  1. Tick the channels each test should use — Patient Email, Patient SMS, Provider Email, and/or Provider SMS.

Tick channel(s)

  1. Click a row's Edit (gear) to review or set that test's message templates.

Click edit

  1. Edit then click Save to apply, or Exit to leave without saving.

Edit & save

Field reference

Column

Notes

Patient Email / Patient SMS

Notify the patient by email or text message.

Provider Email / Provider SMS

Notify the ordering provider by email or text message.

Edit

Open the per-test template detail for the enabled channels.

Notes

  • Notifications are only delivered if the underlying email/SMS channels are configured in Application Properties.

  • A message template can be set per channel and per test; where none is set, a system default is used.
