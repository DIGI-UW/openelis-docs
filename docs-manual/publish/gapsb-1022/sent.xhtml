Overview

Sent Messages is the delivery log for the laboratory. The page describes itself as Every message the laboratory sent or tried to send: reports, alerts, notices, notification triggers and channel tests. Each message is one row, with the time, the kind of message (Product), the lab number it relates to, a masked recipient, the channel, the delivery status and the number of attempts. Expanding a row shows the message itself and each delivery attempt. Channels are set up by an administrator under Notifications → Channels (see Step 5).

On the instance used for this page no channel was set up, so every message shown is Failed, and the only messages present were channel tests and one notification. A successful send and the Report, Alert and Ready notice products have not yet been verified on a live instance.

Step 1: Open Sent Messages and filter the list

Go to Main menu → Reports → Routine → Sent Messages. The list loads on open, newest first.

Above the list are the filters:

  • Product: All, Report, Alert, Ready notice, Notification or Test.
  • Status: All, Queued, Sent, Failed or Skipped.
  • Channel: All, Email, SMS or WhatsApp.
  • From and To dates, Lab Number and Recipient.

Set the filters and press Search. Clear filters appears once a filter is set.

The list has the columns Time, Product, Lab number, Recipient, Channel, Status, Attempts, Sent by and Action. Recipients are masked (for example re•••@example.org or +675•••••000). A failed message shows the reason under its status, for example Email is not set up. Messages that are not tied to an order show a dash in Lab number.

Figure 1. Sent Messages filtered to Product Test: four channel tests by email and SMS, each Failed because the channel is not set up, with one attempt each.

Step 2: Read a message and its attempts

Press the arrow at the start of a row. The expanded row shows the Subject and Message that were sent, and under Attempts each delivery attempt with its time, channel, status and reason.

Figure 2. An expanded channel test: the subject "OpenELIS test message", the message text, and one attempt by Email that Failed with "Email is not set up".

Step 3: Send a message again

Press Resend on the row. A notification reads Message queued again. and a new row for the same recipient and channel appears at the top of the list with its own time. The original row is kept unchanged.

Figure 3. After Resend: a new row at 5:46:38 PM for the same recipient above the original at 5:46:25 PM. With email not set up, the new row is Failed with 0 attempts.

Step 4: Find failed messages on one channel

To check one channel, set Status to Failed and Channel to the channel, leave Product at All, and press Search.

Figure 4. Status Failed and Channel SMS: one SMS channel test, Failed because SMS is not set up.

Step 5: Check the channels (administrators)

Channels are set up once and used by every message the laboratory sends. On the Notifications page (breadcrumb Home / Admin Management / Notifications), the Channels tab lists Email, SMS and WhatsApp, each with its status, Last successful send, Send test and Edit. The page also has the tabs Triggers, Templates and Delivery Settings. How to set up channels, triggers, templates and delivery rules is described in Admin: Set up notification triggers, templates, channels and delivery.

Figure 5. Notifications, Channels tab: Email, SMS and WhatsApp all Not set up, with Last successful send: Never.

Send test opens Send a test message with an Address field and Close and Send buttons. When the channel is not set up, Send shows the reason in the dialog (for example Email is not set up), and the test is recorded on Sent Messages with Product Test.

Figure 6. Send a test message for Email: the address entered and the message "Email is not set up" after Send.

Tips

  • If every message is Failed with Email is not set up or SMS is not set up, ask your administrator to set up the channel (see Admin: Set up notification triggers, templates, channels and delivery), then use Resend.
  • Resend creates a new row rather than updating the old one, so a message can appear more than once (OGC-1551). Use the time and the Attempts column to tell them apart.
  • A resent message that could not be attempted shows Failed with 0 attempts. The notification row on the test server showed the same combination. Treat the reason text, not the attempt count, as the explanation.
  • The breadcrumb on this page reads Home / Sent Messages, without Reports, although the page is opened from the Reports menu.
