Set up QC for an instrument

At a glance

PurposePrepare one analyzer-and-test pair so that the control results the analyzer sends are evaluated against Westgard rules and appear on the QC Dashboard.
You'll end up withAn analyzer in the Analyzers List, an Active control lot for the analyzer and test, and a reviewed Westgard rule set for the pair shown under Configured Rule Sets.
Who does thisWhoever brings an instrument or a new test into QC monitoring — typically a laboratory quality officer or section supervisor, once per analyzer and test. Access is set by user permissions and can be configured by your administrator.
Before you startThe analyzer is connected to OpenELIS and listed under Analyzers; the first control lot's insert (lot number, level, expiry, mean and SD); a decision on which Westgard rules your SOP applies and which count as rejections.
WhereMain menu → Analyzers → Analyzers List, then Analyzers → Quality Control → Control Lots and Rule Configuration

Statistical QC in OpenELIS is built from three things per analyzer-and-test pair: the analyzer itself, an active control lot with its statistics method, and the Westgard rule set that decides which control results are warnings and which are rejections. This page walks the one-time setup in that order. Once it is done, day-to-day work is the recurring lot change (Receive and activate a control lot) and the daily review (Review QC and act on violations).

Step-by-step

Step 1. Confirm the analyzer exists. Open Analyzers → Analyzers List. Tiles show Total Analyzers, Active, In Setup and Needs attention counts; below a search box and Status filter, each analyzer is listed with its Name, Connection, Test Units, Type, Status and Actions. The analyzer must be listed here; an analyzer still at Status Setup, or counted under Needs attention, can still have control lots and rules registered, but it will not deliver control results until its connection is completed. If the analyzer is missing, add it with Add Analyzer (see the analyzer integration pages of this manual).

{{IMG:01-analyzers-list.png}}

Figure 1. The Analyzers List with thirteen analyzers registered — two Active, six still In Setup. The notice at the top flags an analyzer holding results until its unknown codes are mapped.

Step 2. Register the first control lot for the analyzer and test, following Receive and activate a control lot. Saving the lot creates the Westgard rule set for that pair automatically.

Step 3. Open Analyzers → Quality Control → Rule Configuration. Under Configured Rule Sets the pair now appears with its Analyzer, Test and an Enabled Rules count out of 8 — 4/8 for a newly created set. Open the row's Options menu and choose Edit.

{{IMG:02-rule-configuration-list.png}}

Figure 2. Rule Configuration listing one analyzer-and-test pair — Cepheid GeneXpert (ASTM Mode) with HIV Viral Load(Serum) — at 4 of 8 rules enabled.

Step 4. The Edit Rule Configuration dialog is headed with the analyzer and test and groups the eight rules into Rejection Rules and Warning Rules, each with a count of enabled rules. Every rule has an on/off toggle and a Severity choice of Warning or Rejection. The Rejection Rules group opens expanded; expand Warning Rules to see the other five rules and their one-line definitions.

{{IMG:03-edit-rule-configuration.png}}

Figure 3. Edit Rule Configuration for that pair, with Rejection Rules expanded at 3 of 3 enabled — 1:3s and R:4s set to Rejection, 2:2s to Warning — and Warning Rules collapsed at 1 of 5.

Step 5. Set each rule to match your SOP: turn a rule on or off with its toggle and choose whether a breach is a Warning or a Rejection. Save stays greyed out until you change something, and becomes available as soon as a toggle or severity changes.

{{IMG:04-edit-rule-configuration-changed.png}}

Figure 4. The same dialog after switching 2:2s from Warning to Rejection; Save is now available.

Step 6. Choose Save. The dialog closes and the Enabled Rules count in the list updates.

Rule reference

The eight rules, with the definition text shown in the dialog and the defaults created with a new lot (as observed on version 3.2.2.0). Rules 1:3s, 2:2s and R:4s sit in the Rejection Rules group; the other five sit in the Warning Rules group.

RuleDefinition shown in the dialogDefault
1:3sOne control exceeds ±3SDOn, Rejection
2:2sTwo consecutive controls exceed ±2SD in same directionOn, Warning
R:4sRange between two controls exceeds 4SDOn, Rejection
1:2sOne control exceeds ±2SDOff, Warning
4:1sFour consecutive controls exceed ±1SD in same directionOn, Rejection
10:xTen consecutive controls on same side of meanOff, Warning
3:1sThree consecutive controls exceed ±1SD in same directionOff, Warning
7:TSeven consecutive controls trending in same directionOff, Warning

Tips

  • The Rejection Rules and Warning Rules groups are fixed groupings; the actual severity of each rule is the Severity radio inside it. A rule in the Rejection Rules group can be set to Warning (2:2s is, by default).
  • The system does not stop you from turning off every rule with Rejection severity. Keep at least one rejection-level rule enabled, otherwise out-of-control runs will only ever be reported as warnings.
  • Analyzer types are served by the Analyzer Bridge. Where no Bridge is configured, Analyzer Types shows “Analyzer types could not be loaded — Check the Analyzer Bridge connection, then try again”, the type list is empty, and Add Analyzer cannot be completed because no type can be selected.
  • Rule sets are created only when a control lot is saved. If a pair is missing from Configured Rule Sets, register a control lot for it first.
  • Known defect (3.2.2.0): the Test shown in the list and in the dialog heading may not match the test selected on the control lot (for example VGM for a lot saved against Hb). The rule set still applies to the pair you created.

Not yet available

  • There is no per-rule requires corrective action setting on this screen.
  • Rules cannot be copied from one analyzer-and-test pair to another; each pair is edited on its own.
