OpenELIS 3.3.0. This page describes the Validation page as it works in 3.3.0 (not yet released at the time of writing), where one search bar loads the queue. In 3.2.2 and 3.2.3 the same queue and review panel are reached from Validation → Routine, By Order, By Range of Order Numbers and By Date. Sites on earlier releases use Validate and release results, which describes the previous worklist with its Save / Retest checkboxes.

Overview

The Validation page loads a queue of results waiting for validation, chosen by lab number, lab unit, date or patient. Above the queue, a row of filter chips counts the rows carrying each signal, and two lane tags count the whole queue as Clear or Needs review. Each row opens a review panel in place, showing the result in context (reference and critical ranges, method, analyser, who entered it and when) with the release, correction and retest actions together, and a reference block holding notes, QC, order information, history and attachments.

Each result is decided in its own panel, or the whole Clear lane is released at once with Release all clear. A row is Clear when the result is inside its reference range, carries no flag, has no open non-conformity, has not been changed after it was saved, is not critical or awaiting acknowledgment, and has no recorded quality-control failure. Anything else puts the row in Needs review.

Step 1: Open the Validation page

Open Main menu → Validation. The page opens with an empty queue that reads There are no records to display, under a search bar with these controls:

  • Search: a lab number. The hint beneath it reads A range: A..B, or A.. for A onwards.
  • Lab Unit: the test unit, for example Hematology or Biochemistry.
  • From and To: a date range.
  • Search by patient: opens a patient search (see Other ways to load the queue).
  • Load results: loads the queue for what you have chosen.

{{IMG:v6-01-open-validation.png}}

The Validation page before anything is loaded.

Step 2: Load a lab unit and read the queue

  1. Choose a unit in Lab Unit, for example Hematology, and click Load results. The results awaiting validation for that unit load.

  2. Read the header before the rows. The legend explains the red flag icon (Sample or Order is nonconforming or Test has been rejected) and the QC failed tag (A quality control covering this result failed; the non-conformity is still open). Release all clear sits at the right with the number of rows in the Clear lane (Step 8). The filter chips below count the rows carrying each signal: All, Needs review, NCE, QC fail, Modified, Ack pending, Critical and Abnormal. The two lane tags beneath them count the queue as Clear and Needs review.

  3. Scan the rows. Each row shows Sample Info, Test Name, Normal Range, Result, U (k=2), Check before release and Past Notes. A result outside its normal range carries an amber bar and an Abnormal flag; a result inside its range carries a green bar and no flag. A row that carries a signal shows a Review → link in Check before release, under any signal chip. A row in the Clear lane carries neither; open it with the chevron at the left.

{{IMG:v6-02-queue.png}}

The Hematology queue: the legend with the QC failed tag, Release all clear (6), the filter chips, the lane tags and one row per result.

Step 3: Narrow the queue with a filter

Click a filter chip to show only the rows it counts, Abnormal for example. The chip highlights and the count at the foot of the table follows the filter. The Clear and Needs review tags keep counting the whole queue, so they do not change as you filter. Click All to return to the full queue.

{{IMG:v6-03-filter-abnormal.png}}

The Abnormal filter applied: two of the eight rows remain, while the lane tags still read Clear: 6 and Needs review: 2.

Step 4: Open a result for review

Click Review → on a row that needs review, or the chevron at the left of any row. The review panel opens underneath it, headed by the lab number, the patient and the patient's identifiers, and shows:

  • Result with its units and a Normal or Abnormal tag, and the Reference range.
  • Critical range, Method, Analyser, Entered by and Entered on. Fields the laboratory has not captured read Not recorded.
  • The Validation note and its Visibility (Step 6).
  • The actions: Validate & release, Modify result, Send for retest and Refer this test.
  • A REFERENCE block with Notes, QC, Order info, History (this analysis) and Attachments.

{{IMG:v6-04-review-panel.png}}

The review panel for an abnormal result, with the actions and the REFERENCE block.

Step 5: Check the history before you decide

In the REFERENCE block, expand History (this analysis) to see the entries for this analysis: WHEN, EVENT (Created, Result, Status), DETAIL and BY. As the note under the table says, patient trends live on the patient record and Westgard rules on the QC dashboard.

{{IMG:v6-05-history.png}}

History (this analysis) expanded: the analysis was created, the result entered, and its status changed from Not started to Accepted by technician.

Step 6: Add a validation note

Type in Validation note if the decision needs explaining, then set Visibility:

  • Internal keeps the note inside the laboratory.
  • Send with result puts the note on the patient report. This option is selected by default, and the panel says so: This note will appear on the patient report.

The note is recorded against the validation step automatically; the panel shows Context: Validation (recorded automatically).

{{IMG:v6-06-validation-note.png}}

A validation note typed into the panel, with Visibility set to Send with result.

Step 7: Release the result

  1. Click Validate & release.

  2. If your laboratory uses electronic signatures, the Electronic Signature dialog opens. It shows who is signing, the Action (for example Validate and release Red Blood Cells Count (RBC)(Whole Blood) for accession and the lab number) and the Signature Meaning, Validated and Released. Enter your password and click Sign. The dialog also offers Cancel. The dialog notes that signing creates a legally binding electronic signature per 21 CFR Part 11.

    {{IMG:v6-07a-signature.png}}

    The Electronic Signature dialog for releasing one result, during an active signing session.

  3. The result is released, the row leaves the queue, and the filter counts and lane tags drop to match. On the Results page the released test then reads Results final.

    {{IMG:v6-07b-after-release.png}}

    The queue after the release: the abnormal RBC row has gone, leaving All (7) and Needs review (1).

Step 8: Release every clear result in one action

  1. Load the queue you want to release. When it holds rows in the Clear lane, Release all clear is enabled and shows how many rows it would release. The count is the Clear lane, not the whole queue. For one order of four Hematology results, three inside their reference ranges and a Platelets count above its range, the lane tags read Clear: 3 and Needs review: 1, and the button reads Release all clear (3).

    {{IMG:v6-08a-by-lab-number.png}}

    One order loaded by lab number: three results in the Clear lane and one abnormal result.

  2. Click Release all clear. The Release all clear results dialog says what the lane means before you sign: These 3 results are in the Clear lane: in range, no recorded QC failure, no non-conformity, not modified, not critical. A result that stops being clear before the release is skipped. Releasing commits one e-signature for the whole set. It then states the scope of the check: Clearance checks the reference range, result flags, non-conformities, edits after save and critical acknowledgment, and stops any result with a recorded quality-control failure. It does not confirm that quality control was performed. A table lists each result with its Lab No., Test Name, Result and Normal Range.

    {{IMG:v6-08b-release-all-clear-dialog.png}}

    The confirmation dialog for three clear results, with the scope of the clearance check and the rows it will release.

  3. Click Release all clear (3) in the dialog (it also offers Cancel). Where electronic signatures are on, the Electronic Signature dialog opens over it with one signature for the whole set: the Action reads Release 3 clear result(s) for and the lab number, and the Signature Meaning is Validated and Released. Enter your password and click Sign.

    {{IMG:v6-08c-bulk-signature.png}}

    One electronic signature for the three clear results.

  4. The clear rows leave the queue and the counts drop. Rows that need review stay where they are. The button reads Release all clear (0) and is disabled, with the reason written beneath it, here 1 results in this queue carry something to check before release. Most common: Abnormal. Decide those rows one at a time from their review panels (Steps 4 to 7).

    {{IMG:v6-08d-after-bulk.png}}

    After the bulk release: the abnormal result stays in the queue, and the text beneath the disabled button says why.

  5. Once every row has been decided, the text beneath the button reads Nothing is waiting for validation. and the table reads There are no records to display. All four tests read Results final on the Results page.

    {{IMG:v6-08e-empty-queue.png}}

    The order once every result has been released: nothing is waiting for validation.

Step 9: Correct a result before releasing it

Click Modify result to correct a value without leaving the queue. The panel adds a New result field holding the current value, relabels the note field Reason for modification with Visibility set to Internal, and replaces the usual actions with Save modification and Cancel.

{{IMG:v6-09a-modify.png}}

Modify result open on a Hemoglobin row, with the corrected value and the reason for the change.

Enter the corrected value and the reason, then click Save modification. No signature is asked for at this point. The row stays in the queue with the new value, gains a Modified chip and a Review → link in Check before release, and is counted by the Modified filter; it moves from the Clear lane to Needs review. The reason appears in the row's Past Notes with its visibility and timestamp. The result still has to be released.

{{IMG:v6-09b-after-modify.png}}

After saving a modification: the corrected value 12.90, the Modified chip, and the reason carried into Past Notes.

Step 10: Send a result back for retesting

Click Send for retest. The panel switches to a confirmation step: the note field becomes Note for the bench, Visibility switches to Internal, and a red Send for retest button appears beside Cancel with the explanation The result goes back to Results Entry and the pipeline restarts at level 1.

{{IMG:v6-10a-retest.png}}

The retest confirmation step, with a note for the bench explaining why the result is going back.

Write the note for the bench, then click the red Send for retest to confirm. No signature is asked for. The row leaves the queue and the counts drop. On the Results page the test reappears for entry with the status Not accepted by biologist.

{{IMG:v6-10b-after-retest.png}}

The queue after a confirmed retest: the Hematocrit row has gone back to Results Entry, leaving All (6).

Other ways to load the queue

  • By lab number. Type a lab number in Search and click Load results to load one order (Step 8 uses this). The hint beneath the field describes a range: A..B, or A.. for A onwards.

  • By patient. Click Search by patient. A patient search opens with Patient Id, Previous Lab Number, Last Name, First Name, Date of Birth and Sex, and Search, External Search and Clear buttons. Search, pick the patient from the results, and the panel shows Selected patient: with the name and a Clear link. Click Load results to load that patient's results.

    {{IMG:v6-11a-search-by-patient.png}}

    Search by patient, before a search.

    {{IMG:v6-11b-patient-queue.png}}

    The queue for one selected patient: a modified result awaiting review and one clear result.

  • Auto-validated results. When the queue is loaded by lab number, an Include auto-validated toggle appears above the table, off by default. Switching it on adds an Auto-validated results section beneath the queue, headed with its count and the note Released at result entry without a validator; shown for review only. For an order with none it reads No auto-validated results for this accession. Results a validator released, including with Release all clear, are not listed there.

    {{IMG:v6-11c-auto-validated.png}}

    Include auto-validated switched on after a bulk release: the three released results are not listed, so the section reads Auto-validated results (0).

Tips

  • Electronic signatures are a laboratory setting. Where they are on, releasing asks for one; correcting a result and sending it for retest do not. The first signature of a session asks for your username and password; after that the dialog shows You have an active signing session. Enter your password to continue. How to turn them on is in Electronic Signatures.
  • The Clear lane records that no failure is known, not that quality control passed. A patient result that has never been QC-evaluated can be Clear; a result with a recorded QC failure never is. The confirmation dialog says so in its scope line, so read it before you sign for a set.
  • The lane tags are computed from the whole queue. Filtering changes the rows you see, not the lane counts.
  • Rejecting a result is configuration-dependent. Where it is turned off, the panel says so in place of the button: Result rejection is turned off for this laboratory.
  • Correcting a result moves it out of the Clear lane, so Release all clear will not release it. Release it from its own panel.

Not yet verified

These were not exercised on 3.3.0 while this page was written, and are not described above as behaviour:

  • Rows carrying NCE, QC fail, Ack pending or Critical signals. Those filter chips are present and counted zero. Modified and Abnormal are the signal chips that have been seen on a row.
  • Results auto-validated at result entry. The Auto-validated results section has been seen only empty.
  • Loading the queue by a lab number range or by From / To dates.
  • The Components table for a test with more than one component; only single-component tests were reviewed.
  • The other explanations beneath a disabled Release all clear, such as rows with no reference range or the bulk release switched off by an administrator.
  • Refer this test, which was not clicked.
  • The brief confirmation messages after a release, which were not captured.
