At a glance

PurposeSet up the programs that orders are filed under, and the extra questions reception answers when an order uses one.
You'll end up withAn active program with a domain, one or more lab units and, if needed, an order-entry questionnaire.
Who does thisAdministrators. Access is set by user permissions and can be configured by your administrator.
Before you startThe program's name, which domain it belongs to (Clinical, Environmental or Vector), the lab units that work on it, and the questions reception should answer for it.
WhereMain menu → Admin → Programs. The page sits under Test Management in the breadcrumb.

A program is an initiative that orders are filed under, such as a surveillance programme or a care cohort. Each program has a domain, which decides where it is offered: the page's own help text says reception only sees programs that match the order's domain. A program can also carry a questionnaire, which adds program-specific questions to the order.

Step 1 — Open the Programs list

Open Admin from the Main menu and choose Programs. The list shows each program's Name, Domain, Status and Lab unit(s). Use Search by name and the All domains filter to narrow it. Inactive programs are hidden until you turn on Show deactivated.

{{IMG:01-programs-list.png}}

Figure 1. The Programs list, with the search box, domain filter, Show deactivated switch and Add Program button above it.

Step 2 — Add the program's details

  1. Click Add Program. A New Program panel opens above the list, and the button changes to Close.
  2. Enter the Program Name and, if your site uses them, a Programme Code.
  3. In Lab unit(s), type to filter and select every lab unit that works on this program. You can select more than one. Each unit in the list is shown with its domain, and inactive units are marked Inactive.
  4. Choose the Domain: Clinical, Environmental or Vector. What does each Domain mean? opens a short explanation.

{{IMG:03-program-details-filled.png}}

Figure 2. The New Program panel with a name, code, one lab unit and the Clinical domain selected.

Until a domain is chosen the panel shows Domain is required and Submit stays disabled.

Step 3 — Build the order-entry questionnaire

Skip this step if the program needs no extra questions.

  1. With Visual Builder selected, click Add First Question.
  2. Type the Question Text and choose a Question Type: Yes / No, Choice, Checkbox, Whole number, Decimal number, Date, Time, Short text, Long text or Quantity. The line under the type gives an example of what it is for.
  3. For Choice and Checkbox, add the Answer options with Add option. Remove one with the bin icon beside it.
  4. Click Add New Question for each further question.

The Example pane on the right shows the questions as reception will see them, and updates as you add them.

{{IMG:04-builder-with-preview.png}}

Figure 3. Three questions in the Visual Builder (yes-or-no, a choice with three answer options, and a date) with the Example pane beside them.

Working in JSON

Click JSON to see the same questionnaire as FHIR R4 Questionnaire JSON. You can paste a questionnaire here instead of building it question by question. Validate JSON checks it and reports how many questions it found (for the example above: "Validated — 3 question(s)"). Reformat tidies the layout.

The help text under the editor says that advanced features, such as enableWhen conditions, Quantity units and nested items, can only be edited in JSON, and that the Visual Builder keeps them without showing them.

{{IMG:05-json-view.png}}

Figure 4. The JSON view of the same questionnaire, with Validate JSON and Reformat below it.

Step 4 — Save

Click Submit. The panel closes and the new program appears in the list as Active, with its domain and lab unit.

{{IMG:07-saved-in-list.png}}

Figure 5. The new program, Hepatitis B Surveillance, in the list: Clinical, Active, Serology.

Edit a program

Click the arrow at the start of a row to open that program for editing in place. The editor has the same fields as the New Program panel, plus the program's Status and a Deactivate button. Make your changes and click Submit, or Cancel to leave it unchanged.

Changing the domain

Choosing a different domain on a saved program opens Change Program Domain?. It explains that the change is forward-looking: existing orders keep their program coding and are not re-coded, and the program will only be offered on orders of the new domain from then on. Click Confirm to accept or Cancel to keep the current domain.

{{IMG:08-domain-change-confirm.png}}

Figure 6. The confirmation shown when a Clinical program is switched to Environmental.

Deactivate or reactivate a program

Programs are never deleted. The editor notes "No hard delete — deactivate preserves history."

  1. Open the row's options menu (⋮) and choose Deactivate, or use Deactivate in the editor.
  2. Deactivate this Program? tells you how the program is used. For a program with no orders it says the program "will simply stop appearing for new orders" and can be reactivated at any time. Click Deactivate to confirm.

{{IMG:10-deactivate-confirm.png}}

Figure 7. Confirming deactivation of a program that has no orders.

A notification confirms the change and the program disappears from the list. To bring it back, turn on Show deactivated, where it is listed as Inactive, open its options menu and choose Reactivate. Reactivation happens straight away, with a notification and no confirmation step.

{{IMG:12-reactivate-menu.png}}

Figure 8. With Show deactivated on, the inactive program and its Reactivate option.

Tips

  • After upgrading from a version before 3.2.3.0, check the Domain of every existing program. The upgrade sets existing programs to Clinical (OGC-781 release note), so an Environmental or Vector program will not be offered on those orders until you change it. This step has not yet been verified on a live instance. Confirm before publishing.
  • Deactivating rather than deleting keeps the answers already recorded on past orders.
  • Quantity units, conditional questions (enableWhen) and nested groups have to be written in JSON.
